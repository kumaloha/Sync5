# 小丑牌与主角全量美术生产规格

**日期：** 2026-08-10  
**状态：** 待用户书面规格复核  
**范围：** 60 张小丑牌完整卡图与 8 位主角的正式美术资源  
**不在本轮：** 盲注（现役 25 张压力牌与 4 张终局惊喜已完成设计并由既有规格管理）

本规格覆盖 `2026-08-10-joker-blind-visual-system-design.md` 中与 Joker “不制作栅格插画”冲突的部分；旧规格中的 Blind 设计与其他非冲突约束继续有效。

## 1. 目标

一次性补齐剩余两类美术，并确保批量生产不会发生以下问题：

- 小丑牌中文字、数值、外框位置随生成结果漂移；
- 60 张牌共享同一种无记忆点图形；
- 大图好看，但缩到局内 155×172 后无法识别；
- 主角过度写实、过度抽象，或职业只能靠文字说明；
- 8 位主角像同一人的换装，缺少性别、体型与姿态差异；
- 完整卡图覆盖现有中央插画路径，导致运行时出现“卡中卡”。

本轮不改变机制、数值、卡池和主角被动。

## 2. 已批准的总视觉语言

### 2.1 世界观

沿用现有赛博朋克、玻璃、霓虹舞台语言。新美术不改主题，只解决信息层级、职业可读性和记忆点。

### 2.2 小丑牌

- 小丑牌类别色固定为青蓝玻璃霓虹外框；
- Target / Common / Uncommon / Rare 只通过小面积粉 / 蓝 / 紫 / 金角标与局部热点区分；
- 每张牌使用独立的机制图腾或主体轮廓；
- 中文名称、核心数值与效果文字由确定性模板排版，不让图像模型生成文字；
- 采用已批准的“赛博塔罗图腾、信息优先”方向；
- 图腾面积克制，文字说明区优先。

### 2.3 主角

采用已批准的原创二维赛博动漫人物方向：

- 锐利粗黑轮廓；
- 硬边赛璐璐阴影与大面积纯色色块；
- 完整但适度夸张的人体比例；
- 高饱和个人色，减少真人皮肤和材质细节；
- 职业通过服装、道具、动作和身体语言共同表达；
- 不复制《赛博朋克：边缘行者》的任何具体人物、发型、服装、改造或姿势，只使用高层二维动画设计原则。

统一风格基准为已批准的 DJ 三联候选：街头男性 DJ 与机能女性 DJ 均通过，舞台偶像型 DJ 淘汰。其视觉判断标准为“职业一眼可读、人物非真人、轮廓强、细节不糊成噪声”。

## 3. 小丑牌生产合同

### 3.1 数量与名单

总数固定为 60：8 张 Target + 52 张 Support。ID 与画面提示以 `design/jokers_atlas.md` §6 为唯一出图名单；顺序与 ID 不再变更。

- Target：`twin stair mono triplet lonewolf kaleido shredder wrecker`
- Support（现役/已冻结）：`encore finale turnover tipjar chord neonsign vinyl chorus interest momentum vip glowstick shortcut fourfingers twotone bassline mirror wildcard variation reprise fullcast superfan opener popup rainbow nopair backup rehearsal trio bassclef warmtone cooltone undertone`
- Support（待引擎波次但先出图）：`curtain stopwatch freeze earlyout crescendo segue stilllife declutter stageexit doggybag royalty digger collector doublebill sponsor skint rebrand trim xray`

### 3.2 尺寸

- 局内验收尺寸：155×172；
- 完整卡源图：1240×1376（精确 8 倍）；
- 中央插画源图：1024×1024，无文字、无外框；
- 所有完整卡必须额外生成 155×172 的缩略验收图，但缩略图不作为运行时源文件。

中央插画以正方形母版生成，关键轮廓必须落在中央安全区；合成时允许裁入卡面显示窗，但不得截断决定识别度的主体、手势或道具。

### 3.3 卡面布局

按 155×172 基准定义，8 倍等比输出：

- 顶部名称 / 数值区：约 35 px；
- 中央图腾 / 插画区：约 74 px；
- 底部机制说明区：约 61 px；
- 中文名约 18 px；
- 核心数值约 17 px；
- 中文核心效果约 14 px，最多两行；
- 英文不承担必须读取的玩法信息。

外框、字体、留白、角标、玻璃材质与扫描纹理由统一模板绘制。60 张之间只变化：ID、中文名、核心数值、机制文案、稀有度角标、中央主体和小面积强调色。

### 3.4 两层输出路径

现有 `view/joker_slot.gd` 会把 `assets/jokers/joker_<id>.png` 放入卡面中央显示窗，因此不得把完整卡图直接写入该路径。

每张牌输出：

1. `assets/jokers/joker_<id>.png`：中央插画 / 图腾层，供现有运行时直接读取；
2. `assets/jokers/cards/joker_<id>.png`：1240×1376 完整卡图，包含外框与精确文字；
3. `assets/jokers/previews/joker_<id>.png`：155×172 视觉验收图；
4. `assets/jokers/prompts/joker_<id>.json`：最终生成提示、主体约束和版本信息，便于重做单张而不漂移全套。

### 3.5 文字与数据来源

- 已实装牌优先读取 `data/jokers.json` 的 `cn`、`fx`、`kind`、`rarity`；
- 尚未实装但 ID 已冻结的牌读取 `design/jokers_atlas.md` §5 / §6 的最终卡面；
- 批量出图前生成一份 `assets/jokers/manifest.json`，包含全部 60 张的最终显示字段；
- 模板只读 manifest，不从图像生成结果识别或推测文字；
- 对于 `data/jokers.json` 中尚不存在的 ID，必须逐字采用图鉴中对应条目的最终“卡面”文字，不得临时补写机制或数值；
- 只有当 60 个条目的名称、核心值、效果、类别和稀有度均无空值、占位符或冲突时，才允许开始批量合成；
- manifest 不改变游戏机制，只是美术生产元数据。

### 3.6 中央主体规则

- 每张牌只保留一个主轮廓；
- 遮住文字后，任意两张牌仍应能通过轮廓区分；
- 复杂场景压缩成“主体 + 一个辅助物”，不画完整叙事场面；
- 青蓝框是类别，不允许中央主体也全部只用青色；
- Target 可用小面积粉红热点，Common 青、Uncommon 紫、Rare 金；
- 不能在中央插画里生成卡名、数字、随机英文字母或水印。

## 4. 主角生产合同

### 4.1 角色名单与现有身份

以 `data/characters.json` 和 `view/walker.gd::CREW` 的 8 人顺序为准：

1. `dj`：DJ / 回放 / 青色 / 耳机与唱盘；
2. `magician`：魔术师 / 变数 / 紫色 / 手牌与投影装置；
3. `boxer`：拳手 / 重拳 / 粉红 / 拳套与战斗站姿；
4. `bartender`：调酒师 / 调和 / 橙色 / 摇壶与酒具；
5. `seer`：占卜师 / 预见 / 紫色 / 水晶球与预测界面；
6. `drummer`：鼓手 / 节拍 / 青色 / 鼓槌与电子鼓；
7. `rapper`：RAPPER / 即兴 / 粉红 / 麦克风与节奏手势；
8. `tattooist`：纹身师 / 刻印 / 冰蓝 / 纹身枪、墨盒与个人纹样。

### 4.2 正式选型

从已生成的三联候选中选取以下方向作为第一版正式角色。选择同时保证 4 男 / 4 女、体型差异和职业轮廓差异：

| 角色 | 候选 | 性别呈现 | 选择理由 |
|---|---:|---|---|
| DJ | 左 / 街头原生 | 男 | 用户明确认可；便携唱盘与街头磨损最贴合开局主角 |
| 魔术师 | 右 / 机能专家 | 女 | 与传统燕尾服区分，投影手套直接表现“变数” |
| 拳手 | 中 / 舞台明星 | 男 | 体型最独特，拳套与冠军轮廓在小尺寸最清楚 |
| 调酒师 | 中 / 舞台明星 | 女 | 倒酒动作与橙色长摆形成强职业剪影 |
| 占卜师 | 右 / 机能专家 | 女 | 预测界面把占卜转译成赛博职业而非奇幻法师 |
| 鼓手 | 左 / 街头原生 | 男 | 便携鼓垫比大型鼓架更适合后续局内小图 |
| RAPPER | 左 / 街头原生 | 男 | 麦克风与压低重心的姿势最自然，不像偶像歌手 |
| 纹身师 | 中 / 舞台明星 | 女 | 人体纹样即职业作品，轮廓与其余七人差异最大 |

未选候选保留为将来皮肤参考，不进入本轮正式资源。

### 4.3 每人交付内容

每个角色形成独立目录 `assets/characters/<id>/`，包含：

1. `portrait.png`：1536×2048 全身正式立绘，干净深色背景；
2. `avatar.png`：512×512 头像裁切，脸、发型与职业小道具清楚，可保留统一深色背景；
3. `walk.png`：8 帧向右行走精灵表，每帧 128×128，透明背景，运行时可水平翻转；
4. `dance.png`：8 帧胜利跳舞精灵表，每帧 128×128，透明背景；
5. `prompt.json`：身份、造型锚点、色板、禁止漂移项与最终提示。

portrait 是身份母版；avatar、walk、dance 必须引用 portrait，锁定脸、发型、服装主轮廓和代表道具。动画帧允许减少内饰细节，但不得换装或换脸。

walk 与 dance 的透明像素不得残留抠图色边；若生成工具不能直接稳定输出透明背景，先使用统一纯色底生成，再由确定性流程去底并人工抽查头发、道具和鞋底边缘。

### 4.4 小尺寸规则

- 选人界面现有卡格为 150×196，立绘缩放到该尺寸时仍须读出职业；
- 局内行走角色约 54×70，必须依赖头发、上半身外轮廓和代表道具识别；
- 行走和跳舞帧使用更粗轮廓、更少内线和更大的个人色块；
- 细链条、纹身小字、衣料纹理不得承担身份识别；
- 左右朝向由引擎镜像，避免重复生成两套方向造成身份漂移。

## 5. 生产方式

### 5.1 推荐方式：生成主体 + 确定性合成

采用已批准的混合管线：

1. 图像模型生成小丑中央主体与主角人物；
2. 本地模板合成小丑外框、文字、角标和玻璃材质；
3. 本地脚本完成尺寸、裁切、缩略图与精灵表排布；
4. 每个输出文件通过尺寸、通道、文件名和可读性检查；
5. 单张失败只重做对应主体，不重跑整套。

纯 AI 完整卡图被否决：文字错误、排版漂移和 60 张边框不一致不可接受。纯手绘矢量被否决：60 张独特主体与 8 人角色的产量不现实。

### 5.2 批次

- Joker 以 15 张为一批，共 4 批；
- 主角以 4 人为一批，共 2 批；
- 批次之间只允许修正提示模板和技术错误，不随意改变已批准的总风格；
- 所有中间生成图保留版本，不覆盖上一版；最终选择再复制到标准路径。

## 6. 验收

### 6.1 自动检查

- 完整卡图恰好 60 张；
- 中央图、完整图、缩略图和提示文件 ID 完全对应；
- 完整图均为 1240×1376，缩略图均为 155×172；
- 8 个角色目录与 roster 一一对应；
- portrait / avatar / walk / dance 尺寸与帧数正确；
- PNG 可解码，无意外水印和额外文字；
- manifest 无缺字段、重复 ID 或未冻结 ID。

### 6.2 视觉检查

- 在 155×172 下，小丑牌中文名、核心数值和两行效果可读；
- 遮住文字后，60 张小丑仍具有不同主轮廓；
- 小丑牌第一眼是蓝色类别，稀有色只居次级；
- 在 150×196 下，8 位主角无需读名字即可判断职业；
- 在约 54×70 下，8 位行走角色通过轮廓、个人色和道具可区分；
- 主角保持二维动漫感，不退回真人概念图或低多边形人偶；
- 8 位主角不能出现同脸、同发型、同体型或仅换颜色的情况。

### 6.3 失败处理

- 文字或外框错误：修模板或 manifest，不重生成主体；
- 主体职业 / 机制不清：只重生成该 ID；
- 主角身份漂移：以 portrait 为唯一身份参考重做对应衍生图；
- 小尺寸不可读：先删细节、放大主轮廓，不先放大整张 UI；
- 任何失败版本不得覆盖已通过版本。

## 7. 非目标

- 不制作或重做盲注；
- 不修改 Joker、Blind 或 Character 机制；
- 不调整卡池、稀有度、数值和平衡；
- 不在本轮改写 Godot UI 以整张卡图替代现有绘制；
- 不把未选主角候选扩张成皮肤系统；
- 不模仿或复制任何现有动画作品中的具体人物设计。

## 8. 完成定义

本轮只有在以下条件同时满足时完成：

1. 60 张小丑中央图、完整卡图、实机缩略图和提示记录全部存在并通过检查；
2. 8 位主角的 portrait、avatar、walk、dance 和提示记录全部存在并通过检查；
3. 资源已保存到项目 `assets/`，不是只留在临时生成目录；
4. 生成清单、尺寸报告和视觉联系表可复核；
5. 未触碰本轮范围外的盲注、机制和用户已有未提交改动。
