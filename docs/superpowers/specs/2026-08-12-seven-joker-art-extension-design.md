# 新增七张小丑牌美术扩展规格

**日期：** 2026-08-12

**状态：** 已确认视觉方向，待用户书面规格复核

**范围：** 为七张新增 Support Joker 补齐与现有 60 张完全一致的正式美术资源

**基线：** `2026-08-10-joker-character-art-production-design.md`

## 1. 目标

在不改变现有小丑牌视觉系统、机制或 UI 的前提下，把以下七张新增牌纳入正式资源集：

1. `duo` / 对唱 / S-53 / Common / `+10`；
2. `duet` / 二重唱 / S-54 / Uncommon / `+25%`；
3. `triad` / 三和弦 / S-55 / Common / `+25`；
4. `triplebill` / 三重 / S-56 / Uncommon / `+60%`；
5. `backer` / 后台 / S-57 / Common / `+1`；
6. `bench` / 替补 / S-58 / Uncommon / `+点数`；
7. `boxseats` / 包厢 / S-59 / Rare / `×1.2`。

显示名称、编号、稀有度、数值和效果文案以用户主工作目录当前 `assets/jokers/manifest.json` 中这七条已确认记录为准。实施时只把这七条记录同步到隔离美术分支，不携带主目录中的其他未提交改动。美术生产不得重写机制文案或自行调整数值。

## 2. 不变的视觉合同

七张牌必须直接延续现有最终 Joker 母版，不建立第二套风格：

- 青蓝色赛博朋克玻璃霓虹外框；
- 相同的 1240×1376 完整牌面比例；
- 相同的顶部名称、编号、数值框、中央图窗和底部说明区；
- 相同的字体、字号、留白、扫描线、网格和玻璃材质；
- 稀有度仅通过既有的小面积色彩规则区分：Common 青、Uncommon 紫、Rare 金；
- 图像模型只生成中央主体，不生成牌框、中文、数字、编号或水印；
- 中央图只保留一个主轮廓，缩到 155×172 后仍能凭剪影识别。

现有牌框、渲染器和字号不做风格性改动。若新增长文案出现排版问题，只允许使用既有模板的确定性换行与安全区处理，不缩小整套牌的标准字号。

## 3. 成套记忆结构

采用“成套递进”方案。牌框保持完全一致，关联机制通过中央主体的数量和舞台语汇形成视觉家族。

### 3.1 对子家族

- **对唱：** 两张拟人化扑克牌面对面，共用一支竖直麦克风。剪影必须明确呈现“二者 + 中央麦克风”，不画完整人物或舞台。
- **二重唱：** 两条粗壮的青紫声线光带交缠向上，形成一眼可数的双螺旋。它是对唱的倍率升级，视觉上更抽象、更有能量，但仍明确只有两条主线。

### 3.2 三条家族

- **三和弦：** 三根发光琴弦汇入一个清楚的三角和弦节点，轮廓重心集中，确保缩略图能数出三条线。
- **三重：** 三束并排舞台光柱托起同一块无字演出招牌。它是三和弦的倍率升级，视觉规模更大，但不得在牌内生成任何海报文字。

### 3.3 后台资源家族

- **后台：** 黑暗幕布中伸出一只手，把带钻石符号的支票递向舞台。核心轮廓是“手 + 支票”，人物本体不出现。
- **替补：** 候场长椅上的数张暗牌中，唯一亮起并站立的是一张高牌。高牌只使用既有扑克牌符号，不依赖细小点数文字识别。
- **包厢：** 包厢拱窗中三张人头牌俯瞰下方舞台。核心轮廓是“拱窗 + 三张脸牌”，稀有金只作为局部热点，不取代青蓝 Joker 类别色。

七张主体都使用现有赛博塔罗图腾式材质：黑色硬边结构、青蓝发光边缘、小面积紫或金能量核心。禁止写实场景、复杂背景、人物肖像、随机文字和泛化的同款能量徽章。

## 4. 每张牌的五件套

每个 ID 必须同时交付：

1. `assets/jokers/source/joker_<id>.png`：1024×1024 中央主体源图，透明背景；
2. `assets/jokers/joker_<id>.png`：1024×400 局内中央横图；
3. `assets/jokers/cards/joker_<id>.png`：1240×1376 完整卡牌；
4. `assets/jokers/previews/joker_<id>.png`：155×172 局内验收缩略图；
5. `assets/jokers/prompts/joker_<id>.json`：最终提示、版本和源图 SHA-256。

项目资源总量由 60 张扩展为 67 张；manifest、构建器选择逻辑与资源验证清单同步扩展，但不改变既有 60 张的文件内容。

## 5. 生产流程

1. 从当前机制分支读取七条 manifest 记录并按 S-53 至 S-59 顺序追加；
2. 以现有最终 Joker 中央图为风格参考，为七个 ID 分别生成 1024×1024 主体；
3. 去除生成背景并验证透明通道、边缘与主体覆盖率；
4. 使用现有确定性流程生成 1024×400 局内横图；
5. 使用现有 HTML 渲染器合成完整牌面与 155×172 预览；
6. 写入每张牌的最终 prompt 记录与源图哈希；
7. 运行 67 张资源完整性检查，并制作七张新增牌的联系表进行视觉复核。

每张牌单独生成、单独验收。某张失败时只重做该 ID，不覆盖其余已通过资源。

## 6. 验收标准

### 6.1 自动验收

- manifest 恰好 67 条，ID 唯一、顺序正确、显示字段无空值；
- 七个 ID 的五类文件全部存在；
- source 为 1024×1024，runtime 为 1024×400，card 为 1240×1376，preview 为 155×172；
- prompt JSON 可解析，ID、revision 与 source SHA-256 正确；
- 现有 60 张资源未被修改；
- 所有 PNG 可解码，中央源图具有有效透明区域且无随机文字或水印。

### 6.2 视觉验收

- 七张完整牌放进原 60 张中时，看不出模板、尺寸或视觉年代的差异；
- 155×172 下名称、数值和机制说明可读；
- 遮住文字后，七张牌能凭主轮廓互相区分；
- 对唱与二重唱能看出“同一对子家族的普通版 / 倍率版”；
- 三和弦与三重能看出“同一三条家族的普通版 / 倍率版”；
- 后台、替补、包厢各自一眼对应经济、缓存高牌、缓存人头牌；
- 所有牌第一眼仍属于蓝青 Joker 系统，紫色与金色只承担稀有度和局部焦点。

## 7. 非目标

- 不制作 `trim` / 修剪的新图；它已存在于原 60 张资源；
- 不重做或润色原 60 张小丑牌；
- 不修改 Joker 机制、数值、稀有度或文案；
- 不修改盲注、主角、局内 UI 或卡槽布局；
- 不把七张新增牌扩张成动画、皮肤或新牌框系统。

## 8. 完成定义

只有当七张牌的五件套全部进入项目 `assets/`、67 张资源验证通过、七张联系表通过 155×172 视觉检查，并确认原 60 张资源未漂移时，本轮才算完成。
