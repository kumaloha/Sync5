## 0. 千人千面在优化什么(先说清目标,免得旋钮乱拧)

**不是「难度匹配」。** DDA 的目的从来不是让人人 50% 胜率 —— 是**不让人流失**。
按 `generating.md` 的 P 向量分解,context 层真正管的只有两个分量:

| 分量 | 流失机制 | 对应旋钮 |
|---|---|---|
| **N 新鲜感** | 「都见过了」→ 腻 → 走 | novelty(见得最少的优先上场) |
| **挫败节奏** | 连败 → 「这游戏不适合我」→ 走 | streak_shift(连败降档/连胜升档) |

其余分量(通过率绝对值、技巧空间、运气占比)是**设计常量的领地**,context 不碰。
⚑ 判据:**一个旋钮如果在优化「匹配」而不是「留存」,它不属于这一层。**

## 1. 现状(2026-08-19 已实装)

- m 向量两切片:`streak`(战绩 20 局圈)+ `faces_seen`(每张脸见过几次),存 SaveState;
- 消费端 `Director.roll_run(..., ctx)`:novelty(档内最少见集合里均匀掷)+
  streak_shift(连败 2 降一档 / 连胜 3 升一档,阈值不对称:松手要快、收紧要慢);
- 四开关都开。**08-20 用户整体委托后已落地**:boon novelty(`BlindBoon.roll(rng, seen)`)· 探索型货架
  (`view/shop.gd` 没用过的 Target ×1.5,`Economy.weighted_pick` 可选 `boost`)· 回归局(`SaveState.returning_run()`,
  隔 ≥3 天首局温和+熟脸);剧本状态跳转**尚未**接。⚠ 三个阈值(连败 2/连胜 3、3 天、×1.5)目前在代码里
  (`director.gd` / `save.gd` / `shop.gd`),评审建议进 `context` 节带类型校验 —— 待办。

**🟡 岔 #1(货架方向)**:构筑倾向读出来之后,货架该
**A. 探索型**(偏向你**没**玩过的流派 —— 流派层的新鲜感,与 N 轴一致)还是
**B. 迎合型**(偏向你爱玩的 —— 顺水推舟,上手快但加速腻)?
**推荐 A,且幅度小**(权重乘数 ≤1.5):迎合型在留存文献里是短期指标好、长期内容消耗快的形状。
也可以拍 **C. 不做**(货架保持纯 Director 剧本)。

## 4. 「不被察觉」的工程判据(这条是红线的可执行版)

1. **只有分布,没有确定性。** novelty/streak 改变的是**掷点的分布**,任何情况下不做
   「必出 / 必不出」—— 0 和 1 是攻略网站最容易钉死的两个概率
   (拍板先例:「不应该有任何卡有固定概率」)。
2. **幅度封顶**:档位 shift 一档为上限;货架权重乘数封顶;**一次只让一个旋钮大幅生效**。
3. **攻略可写性测试**(判据):如果攻略作者能写出「连输两把后第 X 局必是 Y」,就越界了。
   现实现全部通过 —— 档内仍是均匀掷,写不出「必」字。
4. **UI 零痕迹**:没有任何界面元素随 ctx 变化(盲注卡/商店文案照旧)。

## 5. 与生成线(`generating.md` §5)的分工 —— 写死

```
生成线(离线, tools):造新内容 → 求解器验证 → 门检坏 → 进 faces.json/tiers
context 层(在线, Director):既有内容池里 **给谁、什么时候上**
```

**生成不读玩家,分发才读。** 两层各自演进互不阻塞;「基于 context 生成**新**关卡」
如果将来要做,做法是生成线扩池 + context 层分发,**不是**在线拼脸。

## 6. 验证方案

- **单测**(已有):ctx 空逐字节等价 · RNG 消耗不变 · novelty 最少见必选 · shift 档规则;
- **hundred 扩展**(待做):带非空 ctx 跑 100 关,四条硬规则(不重复/池内/min_run/非空)不破;
- **真人**:回传上线后量「连败 2+ 之后的次局回访率」,streak_shift 的开关天然可做 A/B
  (按 install_id 分桶 —— 🟡 岔 #2:要不要做 A/B,等拍;不做就只看前后对比);
- **察觉测试**:试玩者访谈只问「你觉得关卡是怎么安排的」——
  答案里出现「它会看我输赢」= 暴露,回炉。
