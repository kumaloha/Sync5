## 0. 职责边界 —— 先划清楚

```
        模型该回答的                          模型不该回答的
   ┌──────────────────────┐          ┌──────────────────────┐
   │ 给定关卡, 玩家会怎样   │          │ 这个关卡该怎么设计     │
   │ 给定想要的, 关卡该多难 │          │ 这样好不好玩           │
   └──────────────────────┘          └──────────────────────┘
                                      ↑ **这不是缺口, 是边界。**
```

## 1. 为什么必须先写对象

「求解」和「生成」都是**关于某个对象的**运算。对象没写死时,这两个运算会各自
长出自己的一份对象 —— 那正是这个项目已经踩过五次的坑
(「规则在游戏里,不在模型里」,`docs/design/gates.md`;根因分析在 `docs/design/tech.md`)。

`docs/design/tech.md` 已经在**一拍**这一层解决了它(`core/beat.gd`,六份编排合成一份,
逐份对账除耗时外逐字节一致)。本文做的是同一件事,但对象是**整局 + 玩家 + 表现**,
而且是**先写规格再对代码**,不是反过来。

# 第一部分 · 游戏是什么(形式化对象)

## 2. 层 1:一局(run)的形式化

### 2.1 状态 `s`

```
s = ⟨ D, H, C, J, g, σ, ρ, k_prev, k_first, F, χ, Z ⟩
```

| 符号 | 含义 | 代码位置 |
|---|---|---|
| `D` | 牌堆 = (抽牌序列, 弃牌堆, 万能牌开关, 规则牌集合) | `core/deck.gd` |
| `H` | 手牌,恒 5 张 | `Phrase.hand` |
| `C` | 缓存,恒满,容量 3(`smallstage` 时 2) | `Run.cache` |
| `J` | 小丑牌 4 槽,槽 0 = Target;**每张带 `state`**(成长计数器) | `Run.joker_slots` |
| `g` | 金币 | `Run.coins` / `Phrase.coins` |
| `σ` | (段号, 段内拍号, 全局拍号) | `Run.section_idx` / `phrase_in_section` / `phrase_index` |
| `ρ` | 本段累计分 | `Run.section_score` |
| `k_prev` | 上一拍牌型 | `Run.prev_kind` |
| `k_first` | **本段第一拍**的牌型 | `Run.first_kind` |
| `F` | 四段的脸,**开局一次掷定** | `Run.run_faces` |
| `χ` | 主角 | `Run.character` |
| `Z` | 盖着的牌(按 **Card 对象**记,不按下标) | `Phrase.hidden` |

⚠ **`k_prev` / `k_first` / `J.state` 是三个容易被漏掉的状态维度** —— 它们不在画面上,
但 `norepeat`/`rerun`/`setlist` 和全部成长牌都读它们。**漏掉一个,§9 的 L2 完备性判据会当场抓到。**

⚠ **`Z` 必须按 Card 对象记**:理牌会重排、弃牌会原位换人,下标键会静默指向另一张牌;
弃掉的牌必须从 `Z` 里删除(牌堆重洗会复用同一批 Card 对象)。

### 2.2 观测 `o(s)`

玩家看到的不是 `s`:

```
o(s) = s  除去  D 的顺序(只知道构成)  且  Z 中的牌面替换为「未知」
```

**这是「不完全信息」的全部来源。** 盖牌族(`blindspot`/`facedown`)扩大 `Z`;
没有盖牌时 `Z = ∅`,`o(s)` 与 `s` 只差牌堆顺序。

### ⚑⚑ `F`(四段的脸)**完全可见** —— 2026-08-08 用户纠正的前提

> 用户原话:「**没有脸信息就没有选牌策略**」。

`F` 在**开局一次掷定**(`Run.reset()`),而且**四张全部对玩家可见**。
它在 `o(s)` 里,不在未知量里。

**这不是新机制,是把已有的信息摆出来** —— 数据一直在 `run_faces` 里,
只是界面当时只显示**下一场**的预告(`NEXT ⚠`),模型也只用了下一张
(`bot.gd` 换旗时只找 `w > section` 的第一个)。

⚠⚠ **这一条是「买牌能不能求解」的全部前提,不是一个细节。**

买牌决策难在三件事:①**后面会遇到什么规则** ②牌堆/货架随机 ③卡与卡的协同。
**`F` 可见直接消掉了 ①,而 ① 恰恰是手写规则最无能为力的那个** ——
手写公式的根本困难是「这张牌接下来能触发多少次」,而那取决于接下来的规则;
规则未知就只能拍一个先验,然后每张新卡补一条(那正是 `_card_ev` 的病)。

**规则已知 ⇒ 买牌价值可以直接算**:装上它,把剩余 N 拍在**真实的脸序列**下打一遍,
和不装的比。**不需要任何手写公式,新卡零改代码。** 详见 §5b。

⚠ 推论:一局在**脸这一维上是完全信息**的。剩下的不确定性只有牌堆、货架、
以及盖牌族制造的 `Z`。**别再把「未来的脸」当成未知量去建模。**

⚠ **求解器必须「用信念选,用真值记账」**(`Solver.Split.belief` vs `.score`)。
混用任何一个,得到的要么是上帝视角的玩家,要么是算错分的账本。

### 2.3 动作 `A(s)`

**一拍内(`Stage.DECISION`)**:

| 动作 | 效果 | 改变可达结果? |
|---|---|---|
| `pick(z,i,on)` | 选中/取消选中一张(手牌与缓存**跨区多选**) | ❌ 纯选择 |
| `sort()` | 按点数排序 | ❌ 确定性重排 |
| `swap(h,c)` | 手牌第 h 张 ↔ 缓存第 c 张 | ✅ 换哪 5 张进计分 |
| `discard(S)` | 弃子集 `S ⊆ H ∪ C`,**立刻原位补牌**,免费 | ✅ 换牌面 |
| `lock()` | 锁定 → 结算 | 终结本拍 |

**商店(两拍之间,每 3 拍一次)**:`buy(j)` · `reroll()` · `replace(j, slot)` · `leave()`

⚑ **`pick` 和 `sort` 在现行模型里是 no-op —— 而在真人那里它们花时间。**
这正是 §2.7 的动机:只有把时间建成代价,这两个动作才在形式上存在。

⚠ **点击与拖拽是两种手势,不许混**(用户拍板):点击 = 纯选择,拖拽 = 对调。
曾有一条「已选 1 张手牌 + 点缓存 = 立刻对调」的捷径把第二次点击**吞掉**,跨区多选选不出来,已删。

### 2.4 转移 `T(s, a)`

```
discard(S)  :  |S| 张进弃牌堆 → 从 D 原位补 |S| 张(随机) → Z 中被弃的键删除
swap(h,c)   :  H[h] ↔ C[c]                      (确定性,集合不变)
lock()      :  Pattern(H) → Settle(链) → ρ += 得分, g += 金币,
               k_prev ← 本拍牌型, 若段首则 k_first ← 本拍牌型
phrase_end  :  缓存驱逐(cache_evict 族) → 小丑牌成长钩子 → σ 推进
section_end :  ρ ≥ target(σ, F) ?  是 → g += 工资, σ.段 += 1, ρ ← 0
                                    否 → run 结束(死)
```

**这一整条已经只有一份实现** = `core/beat.gd`(`begin` / `settle` / `phrase_end`),
游戏与全部探针共用。`Beat.after`(商店节奏 + 判生死 + 工资)尚未收口 —— `docs/design/tech.md` 第 5 项。

⚠ **搬家最容易丢的是顺序**:`Tape` 的 `settle.total` 曾写 `run.section_score + gained_score`
(那时入账在打点之后),而 `Beat.settle` 已经入过账,照抄会把这一拍**算两遍且不报错**。

### 2.5 随机源(四个,必须全部可控)

| 源 | 何时抽 | 谁需要控制它 |
|---|---|---|
| 牌堆洗牌 + 补牌 | 每次 `discard` / 发牌 | **全部配对实验**(共用随机数) |
| 四段的脸 `F` | 开局一次 | 排布实验按臂固定 |
| 商店货架 | 每次开店 | 构筑实验 |
| 脸自带的随机(如 `lostpage` 随机弃 1 张) | 拍末 | 覆盖自证 |

⚠⚠ **比较任何两组东西必须共用随机数。** 这个项目最贵的三次错全是它:
λ 扫描首版独立采样 → 「λ 越大分越低」差点判定设计不成立;
探针 `peek_many` vs `draw()` → 配对差 +7.6±3.3 被当信号查了三轮,统一后 **+0.0**;
盖牌替身独立采样 → 噪声吃掉切法间的真实差异。
**没有标准误的差值等于没有结论。**

### 2.6 目标与判定

**局内**:每段 `ρ ≥ target(σ, F)`,四段全过 = 通关。任一段不过 = run 死。
`target` 走 `Run.section_target_for(table, section, mod)` —— **两处判生死唯一的一份实现**
(`sim.gd` 曾漏乘 `target_mult`,整张 `raisedbar` 在模型里是空气)。

**局外**:见 §6。**局内目标是手段,不是目的** —— 这是 §5 的前提。

### 2.7 ⚑ 时间:本作唯一的闸门,而模型里它现在不存在

> ⚠⚠ **本节的「时间 = 动作的代价 `Σ τ(a) ≤ T`」这个形式已被用户拍板简化**(2026-08-08):
> 「时间约束,我们近似为了**每个 phrase 的弃牌张数**,其他不变,这个可以接受。」
>
> **所以不需要**给每个动作定耗时。`rush`(每拍 6 秒)的建模就是「弃牌张数减少」,
> 而现有的 `beat_discards(dur, section)` 已经是这个形状。
> ⚠ 连带后果:**「手速」不再是玩家参数 `θ` 的分量,而是关卡配置的一部分** ——
> 模型因此少一个玩家参数(下面 §3 的 `θ` 里那个 `τ` 要照此理解)。
>
> **下面的实测(§8.3 交换预算的 binding 曲线)仍然有效**,它量的正是「弃牌/交换能力」对分数的影响。


游戏叫「5 秒乐句」,一拍 8 秒(`rush` 时 6 秒)。弃牌免费之后用户拍板:
**「唯一的闸门是 8 秒钟」**,金币只剩买牌一个出口。

**现行形式**:`data/run.json` 的 `beat_budget{discards: 2, swaps: 5}` —— 动作**次数**上限。
**实测它完全不 binding**:缓存只有 3 张,最多 3 次交换就能搬任意「8 选 5」,而预算是 5,
**一个切法都不剪**(`tools/attrib.gd` 实测提速 0%)。弃牌上限 2 也恰好等于求解器自身的上限。
**即:模型里时间实质上不存在,而它是这个游戏的名字。**

**应有的形式** —— 时间是**动作的代价**,不是次数的上限:

```
一拍的约束:   Σ_{a ∈ 动作序列}  τ(a)  ≤  T(σ, F)
             T = 8s(rush 时 6s),走 Run.phrase_duration_for
             τ = 玩家参数的一部分(§3),不是游戏的常数
```

三个直接收益:

1. **`rush`(−2s)自动生效**,不需要任何特判 —— 它只是把 `T` 调小。
   (改前它对模型是空气:求解器不弃牌、交换预算又永不 binding,S4 那半局等于没有 Boss 规则。)
2. **`pick` / `sort` 在形式上存在了** —— 它们不改变可达结果,只花时间。
   现行形式下它们是 no-op,于是「选了又取消」「反复理牌」这类真人行为在模型里没有位置。
3. **完美玩家 = `τ → 0` 的极限**,而不是另一套逻辑。能力谱因此是连续的(§3)。

⚠ **数据结构已经对了**:`Tape` 的 `pick`/`disc`/`swap`/`sort` **每条都带 `at`**(拍内毫秒)。
差的只是真人局 —— 磁盘上 1067 局**全部是探针产物**(时长 >60s 的只有 1 局,而真人一局 ≈ 294s)。

⚑ **实测(§8.3,960 拍)**:交换预算 `b` = 3 时 56/56 切法全可达、损失 **0.0**
(与现值 `swaps=5` 一致 —— **时间不存在这件事是量出来的,不是推出来的**);
`b`=2 掉 6.7%,**`b`=1 掉 37.8%**。**中间隔着 31 个百分点。**
所以「真人一拍能做几次拖拽」不是一个「最好量一下」的参数,**是一个差一次就让全部读数偏三成的开关**。

⚠ **不许为性能去砍这个数** —— 那是拿平衡换速度。手速预算变紧会让 56 种切法降到 46,
那**首先是拟真修正,提速只是附赠**。

# 第二部分 · 谁在玩

## 3. 玩家 = 策略,是**参数**不是常数

### 3.1 现行形式为什么是错的

现在只有一个玩家:完美玩家 `π*`。真人 = `π*` ÷ **发挥系数**(一个标量,零数据)。

**这个标量假设几乎肯定是错的。** 它断言真人是完美玩家的**等比例缩小** ——
每一拍都少拿同样的百分比。而真人的实际形状更可能是:多数拍接近,**少数拍完全没跟上**
(手忙脚乱、看错牌、时间到了还没锁)。这两种分布的**方差**天差地别,
而通过率是分布的**尾部**决定的 —— 均值一样、方差不同,通过率可以差好几倍。

### 3.2 应有的形式

```
玩家 = π(θ),   θ = ⟨ λ, τ, ε, d ⟩
```

| 参数 | 含义 | 完美玩家 | 规则 bot | 真人 |
|---|---|---|---|---|
| `λ` | 跨拍权重(`本拍分 + λ·E[下一拍]`) | 0.2 | 0(不养牌) | 待拟合 |
| `τ` | 动作耗时向量 `(τ_pick, τ_swap, τ_disc, τ_lock)` | **0** | — | **待 Tape 量** |
| `ε` | 决策噪声(偏离 argmax 的程度) | 0 | 大 | 待拟合 |
| `d` | 前瞻深度(拍) | 1 | 0 | 待拟合 |

**收益一**:「发挥系数」这个错误的标量消失了。Tape 到位时做的是**拟合参数**,
不是「回填一个系数」。

**收益二**:`docs/design/capability.md` 的**缺口 3(手速预算是猜的)从"一个待填的数"变成"θ 的一个分量"** ——
它和 λ、ε 在同一个形式里,可以一起拟合、一起做敏感性分析。

⚑ **实测支持(§8.2)**:`λ` 全谱(0 → 0.4)只解释 **645 分**,而规则 bot 与
最低的 `λ=0` 之间还差 **1894 分(z=+13.2)** —— **`ε` 这一维是 `λ` 的 2.9 倍,
而它现在完全没有形式表达。** 所以「玩家参数化」不是形式上的洁癖,
**是模型里最大的那一维现在根本不存在。**

**收益三**:规则 bot 不再是「另一种东西」,而是能力谱上的一个点。
⚠ 这也解释了那条已经踩到的教训:**同一张脸,规则 bot 量出 +1584、完美玩家量出 −790**
(`freshsheet`)。根因不是 bug,是 `λ=0` 与 `λ=0.2` 是**两个不同的玩家**。
参数化之后,「拿哪个模型去量」变成「取 θ 的哪个值」,是个**显式的实验设计选择**,
而不是一个容易搞混的实现细节。

### 3.3 这一层的验证

**主张:`⟨λ, τ, ε, d⟩` 足以刻画从规则 bot 到完美玩家的整条能力谱。**
证伪方式:**能不能找到一组 `θ` 复现现有规则 bot 的分数分布**(配对 + 分位数对账)。
复现不了 = 三个参数不够,需要第四个 —— **那本身就是有价值的发现**,不是失败。

## 3.4 实测:`λ` 撑不起能力谱,`ε` 才是主导维度

N=60 局/臂,无脸基准,全部共用同一批种子(配对)。

| 玩家 | 总分 | vs 规则 bot(配对) |
|---|---|---|
| **规则 bot**(adaptive) | **4545** | — |
| 完美玩家 λ=0.0 | 6438 | **+1894 ±143 (z=+13.2)** = bot 的 **1.42×** |
| 完美玩家 λ=0.1 | 6726 | +2182 ±166 (z=+13.1) = 1.48× |
| 完美玩家 λ=0.2 | 6932 | +2387 ±158 (z=+15.1) = 1.53× |
| 完美玩家 λ=0.4 | 7083 | +2539 ±171 (z=+14.9) = 1.56× |

**λ 单调递增,所以最接近 bot 的是 λ=0,而它仍然高出 1894 分。没有任何 λ 能降到规则 bot 的水平。**

⚑ **拆开看更清楚 —— 这是本轮最有用的一个数**:

```
λ(跨拍视野)  解释的分数:  6438 → 7083  =   645 分
ε(决策质量)  解释的分数:  4545 → 6438  =  1894 分   ←  是前者的 2.9 倍
```

**「会不会跨拍养牌」只值 645 分,而「会不会枚举 56 种切法、按不按最优打」值 1894 分。**
而现在的模型里 **λ 是唯一的参数,ε 完全不存在** —— 也就是说,
**能力谱上最大的那一维,现在没有任何形式表达。**

**推论(直接命中 §3 的动机)**:「真人 = 完美玩家 ÷ 发挥系数」这个标量假设,
**在 λ 这一维上就已经不成立了** —— 真人与完美玩家的差距主要不是视野,是**执行质量**,
而执行质量的分布形状(多数拍接近、少数拍崩掉)和等比例缩小完全不同。
**→ `θ` 必须至少有 ε;`τ` 由 §8.3 独立证明也必须有。**

### 8.2b `ε` 已实装,两维够到了规则 bot(2026-08-08)

`ε` 的形式 = `value' = value + ε · σ · N(0,1)`,`σ` = 这一拍全部候选值的标准差。
**ε 无量纲** —— 噪声与「切法之间的真实差异」同尺度,所以同一个 ε 在不同配置、
不同分数量级下含义相同。实装在 `Solver._noisy_argmax()`。

| λ=0.2 下的 ε | 总分 | vs 规则 bot(配对) |
|---|---|---|
| 0.0 | 6932 | +2387 ±158 (z=+15.1) |
| 0.5 | 6713 | +2169 ±155 (z=+14.0) |
| 1.0 | 6566 | +2022 ±158 (z=+12.8) |
| 2.0 | 5657 | +1112 ±151 (z=+7.4) |
| 4.0 | 5247 | +703 ±156 (z=+4.5) |
| **8.0** | **4857** | **+312 ±152 (z=+2.1)** |
| 64.0(极限探针) | 4866 | +322 ±152 (z=+2.1) ← **与 ε=8 收敛,噪声已完全支配** |

**→ 主张 8 的正确表述:`λ` 一个人不够(已证伪);`⟨λ, ε⟩` 两维在 `ε≈8` 时够到规则 bot
(+312, z=+2.1,按本项目「显著 **且** 量级 ≥5%」两条判据只满足一条 → 不构成要管的差异)。**

⚑ **但这一行的解读比「对上了」重要得多**:`ε=8` 与 `ε=64` 收敛到同一个数(4857 / 4866),
说明 **ε≥8 时噪声已完全支配,等于「在剪枝后的候选里均匀随机挑」**。也就是说:

> **规则 bot 在「选哪 5 张打」这件事上,水平约等于随机挑。**

而 `6932 − 4860 = 2072` 分正是「从精确 argmax 到完全随机」的全部值域 ——
**与 §8.2 独立拆出来的 ε 那一维 1894 分同量级(两个独立测量互相印证)**。

推论:**`ε` 这一维在 `[0, 8]` 就跑完了整个能力范围**,真人必然落在中间。
⚠ 同时这意味着**不能用 `ε` 去解释比规则 bot 更差的表现** —— 谱到此为止,
再差就得靠 `τ`(手速)或别的维度。

⚠⚠ **这张表是修正后的。第一版被一个 bug 污染过,而且结论是反的**:
`Solver.best_discard` 的收益是 `gain = mean(弃牌后,零噪声) − base.score`,
而 `base` 一度也带上了噪声 —— 噪声选中次优切法时 `base.score` 被压低,
`gain` 就被**系统性抬高** → **ε 越大越狂弃牌**。
污染版给出 `ε=4 → 4732, z=+1.3`(看起来"正好对上了"),修正版是 `5247, z=+4.5`。
**一个人为偏置刚好把结论推到了想要的方向,这是最危险的一种错。**
修法 = 基线取零噪声那一侧(`tools/bot.gd` 的 `b0`),两个口径必须一致。
**建模选择(显式声明)**:`ε` 目前只建模「打哪 5 张」的决策噪声,**不建模「弃不弃牌」的噪声** ——
真人两个都会错,这是一条已知近似。

⚠ **`ε=0` 逐位不变已验**:`ε=0.0` 那一行与上表 `λ=0.20` 那一行**完全相同**
(6932 / +2387 / ±158 / z=+15.1),连标准误都一样 —— 说明 `ε=0` 走的是同一条路径、
**一个随机数都没多消耗**。这条被 `tests/runner.gd` 锁着
(`eq(rng.state, st_before, ...)`),因为**改了 RNG 消耗个数会让全部历史读数静默漂移**。

⚠⚠ **「总分对上」只是必要条件,不是充分条件。** 两个玩家均值相同不代表**行为分布**相同 ——
规则 bot 是「按手写规矩打」,`ε` 是「在最优附近随机抖」,两者的**分数分布形状**
(方差、分位数、崩盘拍的密度)完全可能不同。**本轮只对上了均值,分布未验。**
→ 待办:比分位数而不只是均值;真人 Tape 到位时,拟合的判据也必须是分布而不是一个总分。

# 第三部分 · 怎么求解

## 4. 目标函数

**旧目标**:`max Σ 分数`。
**新目标**(用户原话):「**是每段都达标的情况下的最大化平均分**」

```
max  E[总分]     s.t.  每段 ρ_n ≥ T_n
```

⚑ **约束不需要显式写** —— 没达标 run 就结束了,后面的分拿不到。
所以只要回报定义成「从现在到 **run 结束**的期望总分」,约束就编码在边界条件里。

**这一条修掉了两个东西**:

1. 旧目标在**已经稳过**的段里仍然拼命拿分,而那些分**价值精确为零**
   (段分每段清零 `run.section_score = 0`,通关工资固定 +3 与分数无关 —— 已核实)。
2. 我一度把目标写成 `max Pr[全过]`,那有个反向缺陷:**`U=1` 的区域所有动作无差别**,
   行为退化成随便打。**目标是总分就没这问题。**

**三种局面全部自动涌现,不需要词典序、不需要权重、不需要风险参数**:

| 局面 | 为什么自动对 |
|---|---|
| **必输**(还差 5000、剩 2 拍) | 稳打 → `g>0` → 边界 0 → 期望 ≈ 1600;赌一把 → 3% × `W_{n+1}`,而 `W` 是后面所有段的分 → **赌赢** |
| **有压力** | `g` 跨过 0 的边际收益极大 → 全力拿分 |
| **稳过** | 本段再拿分只加 `s`,留余力抬高 `W_{n+1}` → 哪个大自己比 |

⚠ **可检验的行为预测**:**最后一段 `W = 0`,所以 S4 应该纯粹拿分、完全不留余力。**
接进去之后如果 S4 仍在留余力,说明接错了。

## 5. 四类分层

### ① 参数 — 不进任何地方

```
F = (f₁..f₄)   四段的脸        ← 开局全可见(docs/design/solving.md §2.2)
T = (T₁..T₄)   目标分表
N=4 段 · K=6 拍/段 · 每 3 拍一次商店
```

### ② 索引 — 每个取值一张表

```
I = ( M, A, R, |J|, Z )
  M    倍率向量:各牌型现在值多少        ← 相对基准表的**稀疏偏移**
  A    加分项:乘法链之后落地的固定分
  R    规则牌(近道/四指/双色调)改变牌型判定
  |J|  小丑牌数量 0..4                  ← 决定「能装」还是「必须换」
  Z    本段是否盖牌(观测受限)
```

**压缩靠三条**:

1. **规范化** —— 索引是 `(M,A,R)` 的**净效果**,不是「装了哪些牌」。
   不同牌组产生相同效果时**共用一张表**。
2. **哈希缓存** —— key = 规范化后的净效果,遇到新的才算。
3. **稀疏** —— 大多数小丑牌只碰少数几个牌型,`M` 存偏移不存全量。

⚑ **一局只经历 9 个构筑状态**(开局 + 8 次商店),比较候选时最多 24 个。
**不需要枚举 23⁴,只需要沿路径算。**

### ③ 状态 — 制表

```
t   全局拍号 0..23        (段号 = t/6, 拍位 = t mod 6, **剩余商店次数由它决定**)
g   当前段缺口 0..G       (max(0,·) 截断 ⇒ 每段独立有界)
γ   成长牌计数 (0-2 维)   ← 只对**装了的**成长牌开维度
```

⚠ **`γ` 必须进状态,不能用期望**(用户纠正):成长牌是**路径依赖 + 非线性**的
(「每 12 次弃牌 mult+0.25」是阶梯函数),**用期望会把阶梯抹平,而阶梯正是它的全部意义**。
可行的原因是现役 23 张里成长牌只有 3 张,给定索引下通常 0-2 维,取值 0..24。

### ④ 在线 — 现算,不枚举

```
缓存 3 张 + 手牌 5 张  →  最优解函数 f(8 张, I, 脸) → (最优分 s, 最优留牌)
                          = Solver.best_split, 已有, pair.gd 验过 = 游戏代码
```

⚠ **缓存不抽象**(用户纠正)。它在决策那一刻是已知的 —— 需要枚举的是「未来会怎样」,
不是「现在是什么」。

## 6. 两段式价值 —— 这是本文的核心结构

缓存不进状态 ⇒ `V(t,g,γ)` 不知道缓存 ⇒ 它对不同缓存给出相同的值。
**解法是把价值切成近期和远期**:

```
value(动作 a) =  推演 H 拍(从执行 a 之后的**真实局面**开始, 用真实缓存)
              +  V_I(t+H, g_after, γ_after)          ← 查表, 远期
```

| | 用什么 | 精度 |
|---|---|---|
| **近期** `H` 拍 | 真实缓存 + 真实 `Beat` + 最优打法 | 精确 |
| **远期** | 查表(建表时缓存取该 `(t,I)` 下的平均) | 粗略 |

⚑ **缓存的影响衰减很快**(3 张,每拍都可能被换掉),所以远期不知道缓存的代价有限。
⚠ **`H` 是要定的参数**,而且**可测**:量「缓存对第 `t+h` 拍分数的影响」随 `h` 衰减多快,
衰减到噪声内的那个 `h` 就是 `H`。**先测再定,不猜。**

## 3. 状态转移

### 3.1 拍内（`t mod 6 ∉ {2, 5}`）

```
V_I(t,g,γ) = Σ_{(s,δ)} Pr[(s,δ) | t, I, γ] · [ s + V_I(t+1, max(0,g−s), γ+δ) ]
P_I(t,g,γ) = Σ_{(s,δ)} Pr[(s,δ) | t, I, γ] ·       P_I(t+1, max(0,g−s), γ+δ)

  s = 这一拍得分       δ = 成长牌计数的增量(弃了牌就 +1, 否则 0)
```

⚠ **`(s,δ)` 是联合分布,不是两个独立分布相乘** —— 「弃牌换来高分」这个关系在里面。
⚠ 两处不对称照旧:`s` **全额**进 `V`(目标是总分),`g` 用 `max(0,·)` **截断**(超额不再帮助达标)。

### 3.2 段中商店（`t mod 6 = 2`）

```
V_I(t,g,γ) = Σ_{I'} Pr[I' | I, k(t)] · V_{I'}(t+1, g, γ)
```

**不结算、不清分、不判生死** —— `g` 原样带过去,只换索引。

### 3.3 段末（`t mod 6 = 5`）

```
g > 0 (没达标):  V_I = 0,  P_I = 0                    ← run 结束, 后面一分也拿不到
g = 0 (达标):    V_I(t,0,γ) = 工资 + Σ_{I'} Pr[I'|I,k(t)] · V_{I'}(t+1, T_next, γ)
                 P_I(t,0,γ) =        Σ_{I'} Pr[I'|I,k(t)] · P_{I'}(t+1, T_next, γ)
```

**约束不需要显式写** —— 没达标就没有后续,那是边界条件自己在做的事。

### 3.4 终止

```
t = 24:  V = 0,  P = 1        ← 24 拍走完 = 四段全过 = 通关
```

### 3.5 ⚑ 索引转移 `Pr[I' | I, k(t)]` —— 纠正 1 的落地

**`k(t)` = 从第 `t` 拍起还剩几次商店,由 `t` 唯一决定**(每 3 拍一次)。

所以**不需要「假设不再买牌」**(我原来的做法,系统性低估后续段价值),
而是按**剩余商店次数**建模构筑会变强多少 —— 而那个次数**已经在状态里**,**零额外成本**。

⚠ 建表和决策用**两个不同精度**的索引模型,这是有意的:

| | 用什么 | 为什么 |
|---|---|---|
| **建表**(离线) | 平均构筑增长(从数据估「第 k 次商店后 `M` 平均提升多少」) | 要覆盖所有可能路径,具体候选未知 |
| **决策**(在线) | 真实候选 `V_{I⊕j} − V_I` | 那时候选就摆在货架上,是已知的 |

### 3.6 遍历顺序

```
for t = 23 downto 0:              ← 递减(后面的值先算好)
    for I(哈希里已有的):
        for γ, for g:             ← 同一 (t,I) 内互不依赖, 可并行
            按 3.1/3.2/3.3 三选一
```

## 4. 在线决策

```
拍内:  a* = argmax_a [ 推演 H 拍(a 之后的真实局面) + V_I(t+H, g_after, γ_after) ]
买牌:  j* = argmax_j [ V_{I⊕j}(t+1, g, γ) − V_I(t+1, g, γ) ]
```

⚠ **买牌这一层做不了 DP**(用户早就定了原因:未来货架随机、没有信息),所以是贪心。
但**目标从「这张牌值多少分」换成「装上它之后 `V` 高多少」** —— 求解出来的,不是手写表。

---

## 5. ⚠ 反解目标分的顺序**必须**和 DP 一致

`T_{n+1}` 出现在**第 n 段的边界条件**里,所以改后面的目标分会改前面的值。
**`T` 不再对整张表免费。** 但从后往前逐段反解,每一段仍然是查表:

```
① 定 T_N     ← 在 P(N, g, K, ·) 曲线上查(它覆盖所有 g)
② 定 T_{N−1} ← T_N 已定 ⇒ 第 N 段的值已定 ⇒ 再查一次
③ …直到 T_1
```

**反解顺序 = DP 顺序 = 从后往前。** 「免费」这个性质保住了,**但不能乱序反解**。

---

## 6. DP 是**价值表**,不是决策器

上面的转移里**没有 `max`** —— 因为拍内动作 `a` 依赖**手牌**,而手牌(52 张的组合)进不了状态。

分工:

```
DP     → 给出 V(n,g,r,b) 这张未来价值表
求解器 → 在真实手牌上做 argmax:

   a* = argmax_a [ score(a) + V(n, max(0, g − score(a)), r−1, b) ]
                  └ 真实手牌算出的确定值 ┘  └──── 查表 ────┘
```

## 7. 分数分布 `p_{n,k,b}(s)` 怎么建 —— 三组实测定下来的

`tools/udp.gd` 实测(N=200 局,20 个对照点,判据 = **平均绝对偏差**):

### 7.1 先验 DP 本身:iid 在无商店时成立

| 场景 | 平均绝对偏差 | 结论 |
|---|---|---|
| ① 无脸无商店 | **0.0226** | 偏差均值 +0.0020,**在噪声内** |
| ② 有脸无商店 | ~0.023 | 偏差均值 +0.0025,**加脸不制造相关** |
| ③ 有脸有商店 | **0.0384** | 偏差均值 **+0.0261**,系统性为正 |

**③ 破了,而且方向正好是预测的失败模式**:DP **高估**通过率 = 同一局各拍**正相关**。
商店是原因 —— 买到好牌后面每拍都好,买到烂牌后面每拍都差,**构筑把一局内的拍绑在一起**。

### 7.2 四种建表法的对照

| 建表法 | 平均绝对偏差 |
|---|---|
| A 全段混合 | 0.0384 |
| B 只按拍位 | 0.0380 |
| C 只按构筑档 | 0.0357 |
| **D 构筑档 × 拍位** | **0.0260** |

**D 比 A 降 32%,而且已经压到噪声地板**:场景 ①(iid 本来就成立)是 0.0226,
理论地板 ≈ `0.8 × se ≈ 0.022`。**D 的残余偏差已无法与纯采样噪声区分。**

### 7.3 两种相关是**不同的东西**,必须都修

- **拍位相关**:段中商店买了牌 → 后几拍变强。**S1 最明显**(开局空槽)。B 修这个。
- **局间相关**:这一局整体构筑强弱。**S2–S4 最明显**。C 修这个。

⚠ 我一度只提 B(按拍位),**实测被证伪**(0.0380,几乎没改善)——
它修的是「均值随拍位漂移」,而真正的问题是「同一局所有拍一起好或一起坏」。**修错了地方。**

### 7.4 ⚠⚠ 两个方法论陷阱(都踩过)

1. **判据不能用「偏差均值」** —— 它**奖励错得互相抵消**。
   C 的均值 +0.0106 看着最好,其实是 S1 的负偏(−0.063)抵消了 S3/S4 的正偏。
   换成**平均绝对偏差**,D(0.0260)才真正胜过 C(0.0357)。
2. **分档依据必须事前可知** —— 用「这一段的平均每拍分」分档是**拿答案预测答案**
   (段总分 = 6 × 平均每拍分),偏差当然归零,但表对新配置毫无预测力。
   现用**段首的构筑求解器评分**(`Draft._forward`,独立随机数,中间还隔着 6 拍的随机性)。

### 7.5 `B = 3` 档是被**样本量**定的,不是理论

D 要把样本切两次:`200 局 / 3 档 / 6 拍位 ≈ 67 个/格`。**档太多直方图会变尖、DP 失真。**
要更细的构筑分辨率,得先加样本量。

### ⚠⚠ 7.5b 本节 §7.1 的「偏差均值」判据是**错的**

§7.1 那张表用的是**跨档平均**的偏差均值。而实测发现偏差是**档相关**的:
**低通过率档正偏(高估)、高通过率档负偏(低估)** —— 一平均就互相抵消。

场景③在高通过率档(实测 0.905)的偏差是 `+0.001 / −0.034 / −0.018 / −0.032`, **全是负的**,
而报出来的「均值 +0.026」把它盖住了。

**这是同一个陷阱的第二次**(§7.4 第 1 条刚写完「判据不能用偏差均值」)。
形态上说明:**DP 算出的分布比实际更平** —— 而那正是「实际负相关 ⇒ 分布更集中」的另一种说法。

### 7.6 ⚠ 已知未解:S4 是最差的一段

D 在 S4 仍有 +0.076 / +0.073。最可能的解释是**构筑最强 → 分数分布重尾**,
而独立假设在重尾下最容易失效。**留作已知观察,不假装它不存在。**

## 7b. ⚑ 主要偏差的真凶:幸存者偏差(2026-08-08 定位)

段内改成经验分布(精确)之后偏差仍在 −0.09, 所以它**只能来自段间**。逐段拆开看:

```
S1  −0.0903   ← 要经过 3 次段间转移
S2  −0.0859   ← 2 次
S3  −0.0751   ← 1 次
S4  −0.0465   ← 0 次(最后一段, 没有段间转移)
```

**单调递减 —— 偏差随段间转移次数累积。** 那是幸存者偏差的签名。

**机制**:批 A 是**不死局**(打满 24 拍), 里面包含了那些**在 S1 就该死**的局在
S2/S3/S4 的表现;而真判生死时它们早已出局。不过滤 = 拿「含弱者」的分布去预测
「只剩强者」的情形 ⇒ **系统性低估通关率**。

**修法**:建表用的**所有**数据(`suffix` 与 `trans`)都只用**活到那一段**的局。
`trans` 还要额外条件于「本段达标」—— 只有达标的人才走得到下一段。

⚠ **我一度排除过这个诊断**(理由是「各段偏差不累积」), 那是看着一版比较平的数据
下的判断, 被后来更干净的数据推翻。**排除一个假设也需要证据, 而我当时的证据不够。**

## 8. 两个不动点 —— 都要测,不许假设

```
p_{n,k,b}(s)  ←  求解器打出来的分数分布
      ↓ 建表
V(n,g,r,b)    ←  求解器拿它做 argmax
      ↑───────────────────┘          环 ①

q_n(b'|b)     ←  买牌决策(依赖 V)
      ↑───────────────────┘          环 ②
```

- **环 ①** 用策略迭代,初值 = 现在这个「分数最大化」玩家。
- **环 ②** 只在 3 个档上,规模小得多。

**收敛判据 = 表本身稳定。测不到收敛就停下来报告,不硬接。**

# 第四部分 · 怎么证明它是对的

## 7. 验收判据(三级,从弱到强)

### L0 · 内部一致

所有主张两两不冲突。**当前 `docs/design/capability.md`(「模型的产出只有一个:分数分布」)与
`docs/design/gates.md`(「目标函数不是难度,是留存」)直接打架,而这个矛盾从没被显式解决** ——
那正是「可执行的东西自动变成判据」的入口。本文 §4/§5 就是它的解:
分数分布是 `P` 的**一个分量**,不是 `P` 本身。

### L1 · 与代码逐位对账

按本文的形式化描述写一个**独立参考实现**,同一批种子跑,**除耗时那行外逐字节一致**。
⚠ **参考实现不许照着 `core/` 抄** —— 那是自证。要从文档写。
(手法已验证有效:`docs/design/tech.md` 六份编排对账全部零差异;仓库不是 git 库,
把原版拷成 `tools/_base_X.gd` 再改原版,两版各跑一次对拍,用完删掉。)

### L2 · 完备性(最强,也最值钱)

> **给定本文 + 一局 Tape 日志,能不能重放出那一局的每一个决策点?**

在每个决策点,本文必须唯一确定:**此刻的 `s` / 可选动作集 `A(s)` / 观测 `o(s)`**。

- 漏了一个状态维度 → 重放时撞上「这个动作不在 `A(s)` 里」或「两个不同局面映射到同一个 `s`」;
- **可自动跑、非零退出**,复用两样已验证有效的东西:Tape 的重放链 + gate 的门。

⚑ **和 Tape 的判据正好差一层**:Tape 的完整性判据是「能重放**局面**」
(`docs/design/telemetry.md`,唯一不可推导的是弃牌补进来的牌,所以 `disc` 同时记 `cards` 和 `got`);
L2 是「能重放**决策问题**」。前者验采集,后者验建模。

### 通用纪律(全项目适用,违反即结论无效)

1. **配对 + 共用随机数**;报差值必须报标准误。
2. **判据两条:显著 且 量级够**(现为 `|z| ≥ 3` 且 ≥5%)。
   样本量是自己定的,只看 z 等于让判据跟着预算走 —— **统计显著回答「是不是真的」,不回答「要不要管」**。
3. **证明落在做决定的那条路径上,不是它的定义上**(`raisedbar` 的第一版证明只验了算术,
   而真正判生死的 `sim.gd` 压根没乘它)。
4. **探针/守卫自己要 A/B** —— 注入假 bug 确认它真的报警。
5. **验不了的显式标「未校准」**,不许混在验过的数字里。

### 7.1 实测:时间约束一旦 binding,会急剧非线性地改变决策

N=40 局 × 24 拍 = **960 拍**,逐拍枚举 56 切法,同一批牌面下比不同交换预算 `b`。
(`b` = 一拍内能做几次「手牌↔缓存」对调,即 `τ_swap` 的直接后果。)

| 预算 `b` | 够得着的切法 | 最优分损失 | |
|---|---|---|---|
| **3**(= 缓存容量) | **56.0 / 56** | **0.0** | **基准 —— 精确证实「现在不 binding」** |
| 2 | 46.0 / 56 | 6.9 分/拍 | −6.7% |
| 1 | 16.0 / 56 | 38.7 分/拍 | −37.8% |
| 0 | 1.0 / 56 | 102.4 分/拍 | −100% |

**主张 9(向后兼容)由 `b=3` 那一行证明**:`τ→0` 等价于 `b=∞`,而 `b≥3` 已经与无约束**逐位相同**。
所以把时间建成代价**不会动现有读数**,是纯增量。

**主张 10(binding)成立,而且形状很陡**:

- 现值 `beat_budget.swaps = 5 > 3`,所以**现在一个切法都不剪**,与实测的 `b=3` 行一致
  —— **模型里时间确实不存在**,这不再是推理,是量出来的。
- **从 3 降到 2 只掉 6.7%,从 2 降到 1 掉到 37.8%** —— 中间隔着 31 个百分点。
- ⚑ **所以「真人一拍能做几次拖拽」不是一个「最好量一下」的参数,而是一个
  差一次就让全部读数偏 31% 的开关。** 这是 `τ` 必须用真人 Tape 量准的**量化理由**,
  也把 `docs/design/capability.md` 的缺口 3 从「等数据」升级成「**等数据,而且在它到位之前
  缓存族与时间族的价格一律不可采信**」。

⚠ 本节只量了 `τ_swap` 一维。`τ_disc`(弃牌)/`τ_pick`(点选)/`τ_lock` 同理待量,
而 Tape 的 `at` 字段已经在记 —— **差的只是真人局**(磁盘 1067 局全是探针产物)。

### 7.2 实测:前瞻改走真实跨拍转移之后

`Solver.cache_value` 原本假设「留下的 3 张会原样留到下一拍」,而 `Beat.phrase_end` →
`Phrase.cleanup()` 会按 `cache_evict` **随机弃掉 n 张**,下一拍 `Phrase.start()` 再**补满**。
现在改成:**精确枚举全部 C(3,n) 种驱逐结果取期望**,并且多抽 `n` 张当补牌。

⚠ **不许"取前 n 张"** —— 驱逐是均匀随机的,而 `keep` 的顺序来自切法枚举顺序,
按位置删会让某些切法**纯因为排在前面而显得好**,是个不报错的排序偏置。
⚠ **补牌不能漏** —— 只留幸存者会让下一拍变成 7 张可见(真实是 8 张),
在驱逐族下系统性悲观。**这一条我第一版就漏了**,靠对着 `Phrase.start()` 逐行核对才发现。
⚠ `evict=0` 时:幸存集合恰好一种(= `keep` 本身)、多抽 0 张 → **RNG 消耗与老路径逐位相同**,
无脸探针输出一字未变(4545 / 6438 / 6932 / 7083)。

**配对 A/B 实测(修复前 vs 修复后,同种子同队列)**:

| 脸 | 修复前(假设缓存不变) | 修复后(真实转移) | 变化 |
|---|---|---|---|
| `lostpage` 丢谱(evict 1) | −332.0 ±93.3 (z=−3.56) | **−273.7 ±104.2 (z=−2.63)** | 伤害 −17.5% |
| `freshsheet` 翻篇(evict 3) | −566.3 ±93.6 (z=−6.05) | **−488.1 ±104.6 (z=−4.67)** | 伤害 −13.8% |

**两张脸朝同一个预测方向移动** —— 求解器现在**预见**驱逐、能提前规划,
所以脸伤得更少。**修复前它是被自己的错误模型多坑了一截**,那部分伤害不属于这张脸。
⚠ 诚实标注:两次读数的差(58 / 78 分)**落在各自的标准误内**,所以"移动了多少"没有被统计确立;
被确立的是**方向在两张脸上一致**,且与机制推导相符。

#### ⚠ 副作用:`lostpage` 掉出了覆盖自证的门,而这是**真实情况不是 bug**

修复后 `lostpage` 在 `./tools/gate.sh` 里 z=−2.63 < 3.0,门判「模型里看不见这张脸」。
**诊断 = 案例 ②(对完美玩家真的效应小),不是案例 ①(模型看不见)**,三条证据:

1. **同一机制的硬版量得到** —— `freshsheet` 用的是同一个 `cache_evict` 通路,z=−4.67 显著。
   通路若断了,它也会一起掉下来。
2. **量级本来就该小** —— `warm.gd` 实测养牌总共只值 **+10.4%**;每拍丢 3 张缓存里的 1 张、
   而且求解器能预见,代价是那 10.4% 的一小块。实测 273.7/7038 = **3.9%**,机制上完全合理。
3. **方向对、接近显著** —— 不是 0,是小。

**按 §11 铁律,这里只能标注,不能动内容**:
> **`lostpage` 对完美玩家的上界效应 = −3.9%(真实但小)。真人待定。**
> 真人不会预见驱逐、时间压力下养牌更值钱,所以真人那边可能大得多 —— **等 Tape**。

# 第五部分 · 已知的缺口与近似

## 8. 已知的近似,以及它们偏向哪一边

**这一节是防止倒果为因的最后一道结构性保障:**
每个近似都必须声明它让读数**偏高还是偏低**。方向未知的近似 = 一个不能用来做决定的读数。

| 近似 | 偏向 | 后果 |
|---|---|---|
| 买牌用手写规则 | **低估**上界 | 目标分**系统性偏松**;偏差随小丑牌数增长 |
| 前瞻假设跨拍状态不变 | 在缓存驱逐族下**高估**缓存 | 那几张脸的价格**方向都可能错**(2026-08-07 误判的根) |
| `τ = 0`(完美玩家无手速限制) | **高估**上界 | 目标分对真人**偏难** —— **就让它偏着**,不拍发挥系数 |
| 替身从「牌堆+弃牌堆」抽,不含盖着的牌自身 | **单向**偏保守 | \|Z\|≤5 而池子 ≈44,偏差个位数百分比 |
| 不死局录分 ≈ 有生死判定的分布 | 未知 | 靠闭环重放验(`docs/design/gates.md`) |
| 脸的难度可加 | 已验 ≤2% | 排布搜索按段独立挑脸成立 |

⚠ **铁律(2026-08-07 用户拍板,`docs/design/capability.md`)**:模型测出某张卡价格 ≈ 0 时只有两条路 ——
**① 模型看不见它 / 在它下面算错了 → 修模型;② 对完美玩家真的近零 → 标注「上界不动,真人待定」,不动内容。**
**第三条「改内容直到数字变负」是错的。**
一张脸测出 0,只说明它**不改变上界** —— 而上界是完美玩家的,完美玩家没有手速限制、不会紧张。

⚠ **一般化:不要为了让度量工具好用,而改变被度量的对象。**
工具测不出来时,先问工具的能力边界,再问对象。

## 8b. 能力缺口 —— 模型该管、但现在做不到

### I-1 买什么牌 —— 手写估值,而且新卡在模型里是隐形的

**问题**:`tools/bot.gd::_card_ev` 是一个 `match id:`,**给每一张小丑牌手写一条估值公式**,
配 `data/sim.json` 里每张卡一组手调参数。实测覆盖:13 个分支点名 **18 张** support +
另一张手写表 `counterfactual_tv` 管 **5 张** Target = **23/23,恰好全覆盖**。

**为什么是建模问题**,三条:

1. **新卡默认 `return 0.0`** —— 加第 24 张牌,没有分支 → 估值 0 → 机器人**永远不买** →
   它在所有基于模型的读数里**完全隐形**,而目标分照着一个「这张牌不存在」的世界算。
   **不报错、不崩溃。**
2. **循环论证** —— 尺子是「我手写的这张牌值多少」,被量的是「这张牌值多少」。
   手写值高 → 多买 → 实测贡献高 → 「验证」了手写值。**这个回路没有外部锚。**
3. **量级** —— `tools/coin.gd` 实测**整个构筑值 4.2 倍**(有商店 18654 / 无商店 4410)。
   **分数的大头压在最粗的这一层。**

⚠ 这条病的诊断书项目里早就有,只是没应用到商店上:CLAUDE.md 写过缓存潜力
**不许手写启发式**(「同花势那套是每张新卡补一条规则的老病」),要用同一套 Solver 采样算。
`_card_ev` **就是那个老病的一字不差的形态**。

### I-2 卡和卡的协同 —— 从来没测过

**问题**:`tools/addit.gd` 证明了**脸**的难度可以相加(六对残差 ≤2%),
于是排布可以按段独立挑。但**小丑牌之间从没做过同样的检验**。

**为什么是建模问题**:构筑的核心就是协同 —— 「早抽改基牌」「奖励分前期是神后期过气」
这类机制天生是**非线性**的。脸可加**不蕴含**卡可加:脸是一段一张、时间上不重叠,
而**四张小丑牌是同时在场的**(那正是我上次预判可加性会破时用错的理由的反面)。

⚠ 如果卡之间不可加,那么「单张卡定价 → 相加 → 得到构筑强度」这条链是断的,
而 I-1 的修法(用求解器算单张买牌价值)**默认了它可加**。

## 8c. 表达缺口 —— 模型该表达、但现在表达不了

### II-1 「难」只有一个结果代理,没有来源分解

**问题**:`docs/design/solver_roadmap.md` 定义 `难度 = 1 / 通过率`。那是个**结果**,它回答「多难」,
不回答「**难在哪**」。

**为什么是建模问题**:关卡设计要做的判断是「这一级的难,和上一级是不是同一种难」。
现在模型答不出来,所以「阶梯上升」这句话我建模不出来,只能回头问你 ——
**那次问就是这个缺口的症状。**

**我认为**(标注:这是我的判断,还没有任何外部锚)通过率下降只能来自五个正交的源:

| # | 来源 | 玩家的体感 | 现成的仪器 |
|---|---|---|---|
| ① | **数值压力** `target / E[ρ_基准]` | 「要打更多分」 | 算术 |
| ② | **上界压缩** `E[ρ_完美(c)] / E[ρ_完美(无脸)]` | 「我最好也就这样了」 | `gate.gd` 的配对臂 |
| ③ | **技巧惩罚** `Δ = E[ρ_完美] − E[ρ_贪心]` | 「打错代价变大」 | `formal.gd` 的 `Δ` |
| ④ | **信息惩罚** `E[ρ_上帝] − E[ρ_蒙住]` | 「我算不准」 | `blind.gd` 的 ORACLE A/B |
| ⑤ | **运气暴露** `Var[ρ] / E[ρ]²` | 「我控制不了」 | `formal.gd` 的 `V` |

**五项的仪器全都已经有了,而且都在跑** —— 它们只是从来没有被并排放在一张表上,
也从来没有被当成「难度」的分解。

   ⚠ 无 se(聚合方差,要 bootstrap),只能读趋势。

**⇒ 初步答案(待设计者审)**:四段的阶梯主要由 **① 数值压力**和 **⑤ 运气暴露**承担;
**②③④ 基本不参与**(② 只在 S3 凸一下)。

### II-2 设计意图在模型里没有位置

**问题**:你手写的骨架(S1 认识资源 / S2 视野受限 / S3 机制被掐 / S4 时间)是**设计**,

**后果**:我把它读成了「还没自动化的技术债」。**这是模型缺表达能力,不是骨架有问题。**

### II-3 模型不知道自己不管什么

**问题**:见 §0。模型现在没有位置声明「这件事是边界不是缺口」,

**而可执行性和重要性无关**。
