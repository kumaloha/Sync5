## UI/UX 愿景

### Battle layout

```text
┌──────────────────────────┐
│ Coins   Section   Timer  │
│ Character / Target / Support │
│                          │
│        Cache □ □         │
│                          │
│ Hand □ □ □ □ □ □ □      │
│                          │
│ Discard   Candidate  Draw│
└──────────────────────────┘
```

### Information priority

#### Level 1

- remaining time
- current best pattern
- coins
- Candidate card

#### Level 2

- Cache
- Section target
- active Joker states

#### Level 3

- total score
- historical record
- meta tasks

### Input

Primary:

- Candidate → Hand
- Candidate → Cache
- Candidate → Discard
- Hand ↔ Cache

Accessibility alternatives:

- tap card, then tap destination
- long press for rule detail
- double tap Candidate to discard

### Final-second feedback

- timer contracts faster
- current pattern border pulses
- no pop-up text
- no card obstruction
- no rule change

### Settlement display

```text
Pattern name
→ highlight best five
→ character
→ Target Joker
→ Support Jokers
→ score
→ coins
```

The critical result must be readable within 0.25 seconds.

Longer effects may overlap the next Phrase but cannot block input.

### UX principle

The player should always know:

- what will settle
- how much time remains
- what the next draw costs
- which rule changed the result

### 调色:二次校色的实测(权威 = 五张玻璃卡参考图的辉光带采样)

色板本身在 `../CLAUDE.md`:青 `#1effec` / 粉 `#ff328d` / 紫 `#7642ff` / 金 `#ff9b2b` / 红 `#ff3632`。
下面是定这五个值的过程(原文接在那一行之后):

  **(2026-08-06 二次校色,权威 = 五张玻璃卡参考图的辉光带采样)**:上一轮只对了色值大小,
  **色相和饱和度没对**——五色饱和度全线低 0.07-0.11;**红更是差了 9° 色相**
  (旧 `#ff5f6e` 是 354° 珊瑚粉红,目标 1° 纯正猩红,用户:「真的是一个红色吗」)。
  实测(色相/饱和):粉 .926/.76-.97 · 紫 .713/.66-.89 · 青 .484/.91-1.0 · 金 .085/.84-.98 ·
  红 .003/.78-.99。**改色必须量色相和饱和度,不能只看色值像不像。**

### 背景 = 黑:改底色只做一半会看不出来

终值:局内 `BG0/1/2 = 000000/030308/07070f`,首页底色渐变全归零(原文接在那一行之后):

  (旧海军蓝 101430/181f48/232b62 把舞台抬灰,中间稿 05060f 仍带蓝)。
  ⚠ **改底色只做一半会看不出来**:底色归黑后,**大面积柔光成了唯一还在给背景上色的东西**
  ——首页那三团 1000px 级的角落光 + 档位色柔光会把整屏重新染成青调。柔光同步压到
  0.016~0.055 并收小半径,黑才真的是黑。**画面里的光全部由光效层承担**
  (激光/探照灯/光斑/霓虹边/扫描线),底色不再贡献任何亮度 —— 这与五张玻璃卡参考图一致。

### 盲注档位色的来历

终值:四档递进 蓝 `#23cdff`(`StageTheme.BLUE`)→ 橙 `#ff9b2b`(`AMBER`)→ 红 `#ff3632`(`RED`)→ 粉 `#ff328d`(`PINK`)(原文接在那一行之后):

  (2026-08-06 用户:「没有赛博朋克的感觉,这个蓝和你现在的蓝不一样」——档位蓝换成**电光蓝**,
  采自 `ref_wetfloor_club.png` BASS 卡的最亮饱和像素 #23cdff;旧值 #5fa8ff 是 217° 灰蓝。
  同一轮把 theme.gd 五个主色常量对回规格:**青/粉/紫/金全都比 spec 浅一档**,
  每个"差一点"加起来就是"不像"。**主色的权威 = assets/reference/, 改色先采样, 别凭记忆值**。)
  (逐档升温。前三档是 2026-08-05 用户拍板换掉青/紫/粉那组的结果:「不喜欢这个绿色,红蓝橙可能更好」;
  第四档取调色板里的粉,是「红再往上」的终局色——霓虹灯管最刺眼的就是品红)。

  **2026-08-06 起 4 段全是 BOSS 墙,名字不再区分档位,所以「你打到第几档」这件事完全由颜色 +
  序号承担**——这也是 `tier_stars()` 改成 1..4(直接等于段号)的原因。

### 排版:局内盲注卡、返工史、对齐、首页布局四条

**局内盲注 = 一张牌**(`Widgets.BlindCard`,2026-08-05 用户两轮拍板):摆在**音浪层左边、
和右边唱片对称**的一张竖牌(118×176,竖向中心压音浪轴线 534)。
**分工:HUD 管「当前数值」**(分数/目标、金币、第几拍、进度),
**盲注卡管「你在打什么」**(档位 + BLIND NN/04 + 第 N 场 + BOSS 脸/NEXT 预告)。
`hud.gd` 因此不再有 `section_label` / `mod_label`,信息区从 150 压到 **96**(26..122)。

**返工史(别退回去)**:先做成小丑牌上方的通栏横条 → 用户「盲注太细了,高度 ×2 都不够」→
加高到 668×114 → 仍被否:「**不是我说的风格,大小也不太对**」。
**根因是视觉语言打架**——横条那版套的是首页大玻璃卡(`StageCard`,那是**公示板**语言),
而它旁边就是手牌,同屏两套语言。终稿改成**逐层同构 `PaperCard`**:玻璃体 + 档位色霓虹边 +
115° sheen + 切角内框,排版照抄扑克牌:**左上角标 = 盲注序号(牌的点数位)、中央大字 = 档位
(牌的花色位)、右下倒置角标**;BOSS 脸出现时底部让给 ⚠ 条、倒置角标收起(墙的牌本来就该
长得不一样)。为此把 `PaperCard._neon_text` 提成 `static PaperCard.neon_text(ci, …)`——
**同一屏的卡必须共用同一支霓虹管**,各画各的会飘。
**判据:同一个部件要不要共用,看的是语境而不是概念** —— 首页大卡和商店公示板是公示板语境,
可以共用 `StageCard`;手牌旁边那张必须说卡牌的语言。

**对齐类反馈要查「视觉顶端」而不是几何顶端**:用户说「下面间距小一些」时,数值上卡片上下都是 48,
真凶是页签的 `!` 角标戳在图标上方 12.5px(它才是菜单的视觉顶端)+ 倒影的光填在缝里。
角标收回图标右上角,下缝再多给 3px 找平。

首页布局(2026-08-05 用户拍板,四条):
⓪ **卡片上下两侧的间隔要一样**(各 48):上方 = 信息栏下沿→卡片上沿,下方 = 卡片下沿→页签图标
上沿。信息栏高度和 `TAB_Y` 都是为这个对称服务的,改其中一个要顺手核对另一个;
① **卡片与页签整体比设计稿下移 64**,两者相对距离不变(页签仍压在卡片下沿上 20),
移完页签的文字/下划线贴到屏幕底部;
② **信息栏与卡片等宽** —— 两者的"线"都落在 x 48..672(卡片外框 24..696 内缩 24;
信息栏内缩 8, 所以它的外框再往外让 8)。只加宽其中一个会立刻被看出来;
③ **信息栏要吃满卡片上方腾出来的竖向空间**(高度 = 卡片顶 - 上边距 - 24),
否则卡片下移后上面会空一块;内部头像/字号/货币章随之放大一档,内容按线那圈的**中线**排
(直接 grow 会把可用高度压掉 16,右侧货币章被下边线切掉)。

`hand_top=672` / `HAND_X0`(居中算出)/ `hand_card_y=724` / `cache_y=1024`。改布局改文案 = 改 JSON。
两个按钮与手牌第 1、5 张**同列**,且与缓存牌**中心等高**。音浪轴线 y=534,结算面板必须压在它以下。

### 渲染手法(踩过坑,别退回去)

- **霓虹辉光**:绝不能靠"把同一字形放大几档叠起来"—— 字体在不同字号下字形不同心、基线会漂,
  出来是往右下糊的重影。正确做法:宽光晕用**径向渐变贴图**(天生平滑),贴形光晕用**同字号、小半径的环形偏移采样**
  (半径 ≤5px,采样间距要小于半径,否则能数出分身),最后画锐利核心。见 `PaperCard._neon_text`。
- **倒影**:`-webkit-box-reflect` 是真镜像。做法是挂一个 `is_mirror` 的自身副本,`scale.y = -0.38`
  把整张卡**压扁**进倒影带(1:1 镜像 + 22% 遮罩只会露出一条边框),遮罩用 **shader**
  (vertex 取 `VERTEX.y` 做 varying),因为遮罩必须统一作用在 StyleBox / 字形 / 贴图上。
  见 `PaperCard._mask_material`,参考图 `assets/reference/ref_wetfloor_club.png`。
- **渐隐/光晕一律用渐变贴图或程序贴图**,不要用一叠矩形切片 —— 会出现硬边亮条和台阶。
  **且贴图必须建一次并缓存**(static/成员变量):在 `_draw()` 里每帧 new 的 `GradientTexture2D`
  首帧未生成时整块渲染为**白色**(结算屏踩过)。
- **子节点画在 `_draw()` 之后**。遮罩层要在 `_draw()` 里画,用子 `ColorRect` 会把自绘内容全埋掉。
- **玻璃卡 = 程序化画,且照着素材的像素剖面画**(`Widgets.StageCard`,2026-08-05 定稿)。
  别再凭印象堆效果——量过交接件 PNG 的横/纵剖面,真相是:
  **整张图只有一条线**(图宽 4.9% 处、近白灰度 0.93、alpha 0.99、约 3px),
  **这条线外面 alpha 全是 0**(没有外光晕、没有主色描边),线内侧 0.18→0.07 缓降。
  用户看到的"内框"来自设计稿 html 自己的一层:`inset:34px` 的内衬深底,边缘紧贴白线内侧 3px。
  **2026-08-06 用户拍板推翻内衬做法:「我最初的设计仅仅是一块玻璃板被打了光」**——照 html 搬的
  内衬深底 + 内缩矩形上的渐变贴图有**两组可见矩形边**(渐变贴图为避开圆角内缩 ~9px,四条 alpha
  硬边被用户点名「内置矩形」),已删。现在分层是:**单块玻璃体(圆角多边形逐顶点竖向渐变——颜色是
  y 的线性函数,重心插值精确重现,天生无内部边界;延伸到白线外 8px)→ 26px 点阵(用户钦点保留)
  → 右上受光楔 → 那一条近白细线** → 底部压扁翻转的倒影(兜住首页菜单)。
  **判据(2026-08-06 用户:「玻璃板里面卡别的图层是很难动」):玻璃里不准再出现**有边界的
  板/贴图矩形**(内衬深底、内缩渐变贴图这类);点阵/受光是玻璃自己的纹理和光,由用户逐项挑。
  扫描线和 115° sheen 是全屏动效层(home.gd),扫过卡面但不属于卡。**
  线内缩是**参数**(大卡 30 / 局内板 14 / 玩家条 8),小件不缩会把自己塞满。
  **线 = 档位色霓虹管**(2026-08-06 用户给了五张玻璃卡终极参考图——粉/紫/青/金/红,
  「目标是跟这些一模一样」,**取代** 2026-08-05「外圈纯白」的旧拍板——那是灰白交接件的
  剖面结论):辉光 = 档位色,芯 = 档位色提亮 50%,只在**热点**处烧到近白。
  **光圈亮度分布**(⚠ 按五张参考图**像素实测**,在 `_lit_rim`;第一版目测是**反的**,
  又一次证明「临摹前先量剖面」):**侧边最亮**(全程 v98-100,中段烧到近白 #ffe9f9,
  近底 v≈0.9 有一个凹陷)→ 顶边其次(v93-99,**保持饱和色**不烧白)→
  **底边中段是暗的**(v2-9),只有两个底角亮(v30-60)——目测以为的"底边亮"其实是倒影接缝。
  玻璃体 = **近黑 + ~5% 档位色**(实测中心 v3-7,#0a0408 级;目测版的 20% 太艳)——
  玻璃的"颜色感"主要来自线和光,不是体。**上部光线是一片纵向渐亮**(顶边内侧 40px 仍有
  v16-23,上中体色 v9-12 > 中心 v3-7):顶边往下 38% 渐隐提亮,不是小三角;
  反光面在**左侧**(金/绿/红实测左上 > 右上 v2-5),很淡。点阵间距实测折算 = 26px(现值),
  亮度只比体高 v2-3(alpha 0.09)。采样器思路存档:Godot `Image.get_pixel` 即可,无需 PIL。
  **对账闭环(2026-08-06 定法,以后改玻璃必走)**:`tools/glass.gd` 按参考图同规格
  (1024×1536 黑底 / 卡 750×1230)渲出五色 → `_shot_glass_*.png`,再用同一把剖面尺
  量 REF vs OURS,**数字对不上的就是待办**。这轮靠它抓到三个目测看不见的硬伤:
  ① **`_rounded_path` 只在圆角出点,直边是单段长线** —— 逐点亮度会被两端角的值
  线性填满整条边(底边被填成 v70,参考是 v2-10),必须先 `_dense()` 细分直边;
  ② 辉光**不能用均匀 StyleBox 环**,要和芯共用同一个亮度场,否则底边的暗一路被抬亮;
  ③ **参考的光主要往内渗**:顶边纵剖外侧 −8/−4px 只有 v5/v8,内侧 +4..+24px 却有
  v23/20/16 —— 所以外环薄、内环厚(内环兼顾"上部光线"的近边那截)。
  终值对账:侧边 v98 全程 ✓ / 底边中段 v12(参考 v2-5)✓ / 边色 #fceff5 vs 参考 #ffe9f9 ✓ /
  纵剖内侧 29·23·16 vs 参考 23·20·16 ✓。
- **玻璃的三件套(2026-08-06 用户逐条点名, 缺一件就"不像")**:
  ① **顶部斜切镜面高光**(「顶部侧光哪去了」):**左上一大片三角, 边界是一条清楚的斜线**,
  不是柔和渐晕。对账实测参考在 y=10% 的横扫是 242→76(gold)/377→155(red), 左右差 3 倍、
  台阶 50-74‰;旧值 alpha 0.045 只做出 7‰ —— 等于没有。现为大三角铺底 + 小三角提芯两层,
  两层都用直边保住那条分界(实测台阶 49‰ vs 参考 50‰)。
  ② **线就是玻璃的外缘**(「白光圈似乎没保住卡片, 顶部信息栏也是这样」):玻璃体**收到线上**
  (`r.grow(-ins)`)。旧做法让体比线往外 8px(那是灰白交接件的剖面结论), 卡体会露在光圈外面;
  五张终极参考图里线外只有辉光(纵剖 1/3/5/8 单调衰减, 没有均匀色块)。
  ③ **边缘要有厚度**(「他的边缘还有点立体感你没做」):边不是一条线, 是**有厚度的玻璃棱** ——
  亮芯 → 内侧 2.5px 一道**暗内壁**(棱的背光面, acc 压黑 55%) → 再内 5px 一道极细二次反光。
  三层叠起来才读成"板有厚度";只画单线永远是贴纸。三层的偏移都乘 `k`(尺寸缩放)。
  ④ **光必须有方向 —— 背光侧要留黑**(「立体感还没错, 光线带来的明暗对比不够强」):
  真凶不是亮部不够亮, 是**暗部不够暗**。当时有一层"上部光线"是**满幅**铺开的(alpha 0.06),
  把右侧背光区一起抬到 v87-92(参考只有 v29-76), 高光带辛苦造出的左右差被它整个抵消。
  改成带方向的梯度(左 0.05 → 右 0.004)+ 收窄内环辉光后:
  **左右比 2.8× → 4.8×, 与参考的 4.9× 对齐**(green y=10%: 我们 241→50, 参考 141→29)。
  **判据:对比度看的是暗部, 不是亮部 —— 任何满幅铺开的提亮层都在偷偷杀对比。**
  ⑤ **玻璃体 = 高饱和低明度的档位色, 不是中性黑**(参考 red 体 `#120000` s=1.00 /
  green `#000705` / gold `#080501`):用 `Color.from_hsv(acc.h, acc.s×1.3, 0.082)`。
  旧做法「中性黑掺 3% 档位色」会把红卡画成灰卡 —— 目标图整块玻璃是**暗红**的。
  ⑥ **辉光强度**:参考辉光带 v=0.35-0.51, 旧值只有 ~0.12(饱和采样都采不到) ——
  这是「带光线的部分比目标少」的另一半。外环五道 0.030→0.42, 内环四道 0.26→0.018,
  芯宽 2.2→3.2×k。
  ⑦ **立体感 = 方向性斜面, 不是同心三条线**:光从左上进玻璃、穿过板体照亮**右下内壁**,
  左上内壁反而在阴影里(`_lit_rim` 的 `invert` 模式, lit = 0.12+0.88×(u+v)/2)。
  同心等亮的三条线只会读成三张贴纸。
  ⑧ **四角光圈更强**(「目标中 4 个角都有更强的光线」):实测参考 角/边能量比 1.09-1.41,
  旧值 0.74。做法**必须是沿线增强**(在 `_lit_rim` 的 profile 里加 corner boost) +
  一团很大很淡的角辉光;⚠ 直接在角上贴小而强的径向辉光会读成**四个灯泡**(试过, 很丑)。
  ⑨ **光线分割 = 两个三角的台阶**(「明暗对比他有明显的光线分割」):在受光大三角内部
  再叠一个略小的三角, 交界处形成台阶 —— 那就是那条可见的分界线。
  ⚠ **不要"沿斜边贴一条亮带"**:多边形不受卡片圆角裁剪, 亮带会直接溢出到卡外(试过)。
  **教训:这两处都是"指标达标但形态错了" —— 数字对完必须看图, 角/边比 1.37 的那版
  在图上是四个红灯泡 + 一道伸出卡外的斜条。**
  ⑩ **芯要白, 但只白在侧边中段**:参考边色@50% 侧边是近白(#ffe9f9/#f9f7fd/#eefdfc),
  **顶边却保饱和**(#f392c7/#fb4a47)。所以基色 = acc 掺 42% 白, whiten 只在 sideness
  给到 0.93、topness 只给 0.04。⚠ 曾把基色降到 0.32 白 + 最内圈辉光提到 0.42 纯档位色,
  白芯被辉光染回彩色(用户:「光圈不白了」)—— 芯虽在最上层, 压不过太强的内圈辉光。
  ⑮ **玻璃板 = 全黑板体 + 一条带色带白的边 + 点阵点缀, 没有第四样东西**
  (2026-08-06 用户最终拍板:「把板子中间, 带有颜色的那么大的面积, 去掉, 变黑,
  只剩斑点带颜色点缀」「柔光层全部给我去掉」「我们前面说的边缘光强, 体现在那条
  白边上带着颜色+白的光」)。**「边缘光强」= 那条线本身亮**, 不是线周围有光、
  也不是玻璃里靠边有色 —— 我把它先后做成: 整块均匀染色 → 三角扇径向渐变 →
  向内内缩的渗光环 → 卡外辉光 → 四角光团 → 受光三角 + 交界光带, **六种全是多余的**,
  来回折腾了七八轮。终态只有四层:
    ① 板体 = 近黑(#020203 级), 不掺任何档位色;
    ② 那条线 = 档位色掺 42% 白, 侧边中段 whiten 到近白, 顶边保饱和(见 ⑩);
    ③ 26px 点阵 = 档位色, 越靠边越显(alpha 0.16→0.50), **板体全黑后它是唯一的颜色点缀**。
    ④ **光线的明暗 —— ⚠ 未定案, 用户 2026-08-06 明确表示不满意后中止**
       (原话:「我感觉你做不好。算了, 记录你做的工作」)。下面记的是**当前实现**,
       不是拍板结果;要动这块先看记忆里「玻璃卡 UI 现状与未竟事项」那节的根因分析 ——
       **配色能收敛是因为有采样对账, 光影没收敛是因为一直在目测猜形态**。—— 左上受光大三角 +
       交界处一道发光带, **颜色用近白**(只留 12% 档位色)。
       **光源在右上角, 但形态和直觉相反**(用户 2026-08-06 先说「他从右上角照过来的」,
       我做成"右上角发亮"后被纠正, 又给了右上角放大图:「我说的是这个东西」):
       · **光从右上往左下射**(用户原话) —— 板面沿这个方向衰减:**右上亮、左下暗**,
         受光多边形的直角顶点在 panel **右上**;
       · **右上角另有一块被斜线切出的暗区**(玻璃棱的反射面, 不接受光) ——
         那道斜线是玻璃另一个反射面的边界, 是画面里最显眼的分界, 用**纯黑叠加**画
         (不是"少给光"), 边界才利落;
       · **白热点在「边线」的右上角那一段**(往两边褪回档位色)—— 「光从右上照过来」
         说的是这个热点, 不是板面的亮块;
       · 板面**有颜色**(暗档位色 v0.052), 点阵浮在它上面 —— 不是纯黑。
       ⚠ 改光源方向要同时改「板面受光 / 暗区斜线 / 边线热点 / 内壁透光」四处, 漏一处就自相矛盾。
       **受光面积 ≈ 卡面 1/5**(用户:「别照亮太多, 大概 1/5-1/4」):三角 fx=0.56 / fy=0.72
       (面积 = fx·fy/2 = 0.20)。**面积定死之后, "对比不够"只调 alpha 不调面积** ——
       现值 受光 0.155/0.125、交界带 0.16。
       ⚠ 这一层和"大面积染色"是两件事: 要的是**白光打在黑玻璃上**, 不是给板体上色。
       上一轮我把它俩一起删了, 明暗就没了 —— **删染色时别顺手把光也删掉**。
  **首页的柔光层(角落三团 + 档位色两团 + 全屏 sheen)整体删除** —— 那两团 620/900px
  的档位色光罩住整张卡, **才是用户三次说的"光晕"的真身**;我一直在改 StageCard 的
  边辉光, 所以用户说「光晕毫无变化」。
  **教训(全场最贵):用户说"加强边缘光"时, 我没有确认"边缘光"指什么就开始加东西,
  每加一层都要用户再骂回来一次。指令外的加法比做少了贵得多 —— 先问清边界, 再动手。**

  ⑬ **玻璃的颜色是从边缘渗进来的, 不是整块染**(用户 2026-08-06:「这块板靠中间是偏黑的,
  靠四周(线条)是比较有颜色的……你现在整块板都带着那个颜色」+「衰减要很快, 中间一大块
  是没有, 其实主要就是边缘有」):物理上发光的是**边上那根霓虹管**, 光往玻璃里渗。
  实现 = 纯黑玻璃体 + 一叠**向内内缩的宽描边**, 强度 e^(-0.85·i) 陡衰减, 只占卡宽 ~15%%。
  两条踩过的坑:① **别用三角扇**(中心顶点黑 + 边缘顶点有色):重心插值的等值线**平行于
  每条边**, 长宽比大的矩形会显出一圈圈方形光晕、中心有菱形接缝;
  ② 内缩时**圆角半径要缓慢收**(×0.25):跟着 d 等量减会让内层的角变尖、外层是圆的,
  四角出现"隧道"般的对角接缝。
  **点阵也是有颜色的**, 且同样越靠边越显色(alpha 0.06→0.26 按到中心的距离平方)。
  ⑭ **顶栏与卡片必须是同一种玻璃**(用户:「顶部信息栏跟下面颜色不同, 好突兀」):
  根因是两套做法 —— 卡片走新玻璃体, 顶栏还是 `SLATE` 蓝灰 + 半透黑 override, 色温也差
  (SLATE 217° vs 青档 174°)。解法**不是**让它跟着档位变艳(旧拍板仍成立: 顶栏是玩家
  身份/货币, 滑赛程时整屏换色会吵), 而是**色相跟随、饱和度 ×0.20、明度压到 0.42** ——
  它仍读作"无色玻璃", 但和卡片同一个色温。⚠ 明度给 0.70 时它会**比卡片还抢眼**(实测)。
  ⑫ **颜色靠体、亮度靠光 —— 不能反过来**(用户 2026-08-06:「目标比你暗(除了打光的地方),
  而你该暗的地方填了对应颜色」):实测参考**背光区的饱和度比受光区还高**
  (背光 s0.65-0.90 / 受光 s0.62-0.82)——背光那里是**纯粹的玻璃暗色**, 受光区反而被
  白光冲淡。我原来是反的:给整块玻璃铺一层染色体色补亮度, 再往受光处叠白 ——
  结果背光区 s 冲到 0.81-1.00 比参考还艳、受光区 s 掉到 0.45-0.58 发灰。
  正解:**体压到近黑(v3 级)且保持高饱和, 亮度预算全给受光带**;受光带少掺白(0.22)。
  对账终值:受光 v12(参考 8-14)· 背光 v3(参考 3-10)· 受光 s0.58-0.72(参考 0.62-0.82)。
  ⑪ **玻璃体必须盖到线的外缘**:线是**居中**画的(半个线宽在 line 矩形之外),
  体只收到线中心时, 线的外半边下面就是黑底 —— 读成「光圈和内部玻璃板不贴合」
  (用户 2026-08-06)。体要再往外让**半个线宽 + 1px**。
  **光泽感 = 打光 + 高光带 + 受光不均的边**,三样缺一不可(用户反复指出「像被打光了/你没有这个光泽」):
  ① **受光只做局部,任何满幅的白都要拆掉**。「白白的一层」被查出来有三个来源,全部已删:
  满幅白色柔光洗、淡蓝白的"玻璃膜"(0.10 白)、以及**整块面板的 `PaperCard.sheen()`**
  (那是卡牌/小丑牌槽的语言,套到大玻璃板上就是一层白纱)。现在受光只剩**右上角一个三角亮面**
  (逐顶点渐变,峰值 0.085,边界是一条清楚的斜线),这与设计稿近景一致。
  玻璃体自己的竖向渐变是**暗**的(rgba(24,28,56,.34)→rgba(7,9,22,.42)),别把它换成亮的——玻璃才像被灯照到,
  而不是自发光的板子;**别用径向光晕贴图**,矩形贴图会从圆角溢出去;
  ② **高光带**:右上一宽一窄两道逐顶点渐变的亮带(贴顶边最亮、往斜下散尽),单色多边形太平;
  ③ **边受光不均**:白边不是均匀一圈,按法线和光向(左上)算亮度,迎光处满亮、背光掉到三成
  (`_lit_rim`,走 `draw_polyline_colors` 的圆角路径)。
  **但辉光宽度和受光幅度都要跟着件的大小缩**(用 `k = ins/30`):大卡的绝对值照搬到局内
  560×276 的盲注板上,白圈会显得又厚又"一头毛毛一头很细"(用户 2026-08-05 两次指出)。
  小件 → 薄一圈但层数不减(光泽靠层次不靠厚度)、且几乎均匀。
  **那条线要当霓虹灯管画**:剖面峰值两侧是 0.13/0.10/0.04/0.01 的衰减,所以先铺两侧辉光
  再画锐利白芯;硬边 2px 画出来是"不发光"的。玻璃体要比线**更往外 8px** —— 剖面显示线外侧
  仍有玻璃(0.02→0.13),线是嵌在玻璃里的,不然会显得"不贴合"。
- **底部倒影 = 真镜像,但只镜像"会发光的部分"**。带高 = 卡高的 13.2%(= `height:113.2%`),
  **1:1 不压扁**:接缝一条亮线(卡片底边的镜像)+ 往下延续的圆角与两侧竖轨,随距离渐隐。
  渐隐**必须用 shader 遮罩**(见上条"倒影"),盖一张渐变矩形只能糊颜色、盖不住 alpha。
  **卡片与倒影之间留 12px 缝**:卡是浮在反光地面上的,浮空物体的镜像本就从地面再往下退一个
  离地高度,贴死会像插在地上;而且上方(信息栏↔卡片)有呼吸、下方贴死不对称(用户提的)。
  **镜像轴是霓虹轨的底边,不是外框底边**(裁图实测:那条很亮的接缝线就在轨底);
  **带高 = 卡高的 13.5%**(交接件倒影带的原始比例),光要**铺满底部整排页签的高度**——
  页签是坐在倒影里的。曾把它砍到 6%,那是因为当时倒影画得太实(整块玻璃压扁/渐隐失效),
  一拉长就把页签圈成"第二块板";倒影改成柔光 + shader 渐隐之后,铺满才是对的。
  坑都踩过:① 压扁整块玻璃 → 读成"第二张小卡片";② 只画左右两条竖光带 → 丢了接缝亮线和圆角
  (那是被抠烂的素材点采样误导的);③ 连深色内衬一起镜像 → 把底部页签压暗,实物里深底几乎不反射;
  ④ 镜像层 z_index 设成负数 → 子节点会画在父节点 `_draw()` 之前,被铺满屏的背景整个盖掉;
  ⑤ 倒影**糊的是边缘、形还在**:镜像要留一道柔和的芯(比正面宽、比正面暗、不锐利)再往外散开;
  只铺宽而淡的几道会把倒影整个稀释成看不见(用户:「模糊是边角,不是整体看不见」);
  ⑥ **别用 `draw_set_transform` 做翻转** —— shader 里的 `VERTEX.y` 拿到的是变换**之前**的局部
  坐标,带状渐隐会整个失效(镜像以满不透明度铺下去)。直接算出镜像后的矩形再画:霓虹轨是上下
  对称的圆角矩形,画出来和真镜像等价,而 shader 能拿到正确的 y。
  **教训:判断一块视觉结构前,先把它整段裁出来看图,别只点采样**——素材残缺处的采样值会把人带沟里。
  **手册照做,但它附的 PNG 别直接贴**——抠图是坏的,三条实测证据见 `assets/frames/README.md`
  (代码里贴图分支仍在,放对素材就能接管)。
  尺寸参数一律用**显示像素绝对值**(内框 13 / 圆角 26 / 外框内缩 34),这样 640×972 的大卡
  和 560×276 的扁板才是同一块玻璃 —— 这是不贴图的另一个好处。
  踩过的坑:① 一块深色板 + 细角标 = 没质感(用户「质感差距蛮大」);② AI 原始渲染四周有大黑边
  (霓虹框只占 x14.6%~84.2%),直接贴会缩在卡中央;③ 九宫格切边 60px 会切在霓虹轨上,边框会断
  (要 118px);④ 玻璃体是外框 `inset:34px` 后的 572×904,照着外框 640×972 画会偏大;
  ⑤ **别加外光晕和白光圈**(用户 2026-08-05:「你做了白光圈加外光暈,但 claude design 给的不是这样」)
  ——设计稿那条线外面 alpha 是 0,加了就不像;⑥ 外发光真要画的话,4 道粗环会读成可数的同心圈,
  得 16 道 2px 细描边做连续衰减(这条现在用不上了,留着备查)。
  **方法论:临摹前先把素材的像素剖面打出来**(采样 alpha/灰度找峰),比看图猜快得多也准得多。
- **首页只留柔光,不要激光**(2026-08-05 用户):角落一盏呼吸灯 + 一片极淡光雾即可。
  曾试过设计稿的激光:等亮度白线在 Add 混合下会读成**划痕**(必须沿程渐变:白芯 0%→主题色 7%→透明 95%),
  雾锥单层多边形边是硬的(要叠三层不同张角近似 blur)——最后用户拍板整条撤掉。
- **人群的头要画在前景剪影之前**,否则是一排黑洞。

## ⚑ 点唱片提前收工(M5,2026-08-13 用户拍板「主动结束一拍,就点那个光碟」)

**这不是「给早锁加个反馈」,是补上一个从未实装的玩家动作。**
`early_settle()` 此前是**零调用方的孤立钩子**,而 `_acted_early()` 的判据是
「最后一次动作在早锁线之前」—— 于是「早锁」的真实语义一直是
**「早点动完手然后干等剩下 4.5 秒」**。这解释了那个一直没解释通的差距:
真人早锁率 **8%** / bot **78%** —— 干等的代价对真人是真的,对不感知时间的 bot 是零。
而四张时机卡(速弹/惯性/定格/秒表)全建在这个玩家实际上不会做的行为上。

**交互**:点唱片(`VinylDeck`)。语义天然 —— 唱片是这一拍的时钟化身,点它 =
让这一拍现在结束。**不新增控件,锁定的排版一个像素没动**
(`mouse_filter` 从 IGNORE 改 STOP;⚠ 不能用 PASS,点击会穿到下面的手牌边框上)。

**可点的三个条件**(`_can_early_lock`):决策态 · `elapsed ≥ early_lock_min`(2 秒,
防手滑 —— 这个值的出处是早期主角设计稿的「2 秒后可以提前锁定」(主角系统已删,数值保留),
那条设计早就写着只是从未实装)· **动过至少一次手**(与 `_acted_early` 同源,A4 不许挂机)。

**反馈**(用户从三个方案里选的第 2 案):
- 唱片外圈**金色呼吸环**。⚠ 用金不用青:青是全局 chrome 色,金在这一屏专表
  「时间/收益」(金币、角标都是金),对得上「省下的时间换分数」。
- **中心标签显示省下的秒数**(`3"`)。⚠ 显示的是**因**(秒数)不是果(加成):
  不同构筑的加成不同,而秒数总是那个秒数 —— 没装时机卡时也不会显示一个 `+0%` 的废数字。
  中心标签本来就是纯色圆,数字放进去不占任何新空间。
- ⚠ **第一版只有金环,渲染出来发现几乎注意不到**(一圈细边沉在满屏霓虹里)。
  加了中心秒数之后金环才有了锚点。**「改了视觉就渲染出来自己看」又救一次** ——
  只看代码会觉得「金环够明显了」。
- 意外的好处:它与左边盲注卡的「弃牌余 N 次」形成同一层的一对状态读数
  (左讲资源、右讲时间)。

**连带修掉一个隐患**:秒表原来按 `cur_lock - last_action_time` 算剩余 ——
那是「最后动手时还剩多少」,于是「2 秒动完手然后干等到底」也拿满额,
**它实际在奖励干等**。卡面写的是 "at settle",所以正确的是 `cur_lock - elapsed`:
主动锁定拿真实剩余、自然走完拿 0,一个式子同时对两条路径成立。
