# META —— 资产循环(设计稿)

> **一句话:资产是「玩的时候看得见听得着的东西」,循环的燃料是想再看一眼,不是复利。**
>
> 拍板史:08-09 三层生命周期(日/赛季/永久)→ 08-19「买游戏资产 → 资产变现 → 买更多资产」
> → 08-19 深夜「**没有回本周期,参考蔚蓝星球的道具:几乎是买了你就想玩,玩了你就想买**」
> (这条判死了 v1 的分红阶梯 —— 资产产钱就是回本数学)。
> 本篇接管 `ui_meta.md` META 节的**资产部分**;三层生命周期总表仍看那篇。
> 实现现状 §1,待拍岔路 §7,验证方案 §6。
>
> **红线(全部有结构性保障,不是自律)**:
> ① 循环**碰不到局内经济**(宝石只进资产,力量只经券 —— 券日清零);
> ② **不许永久数值力量**(ui_meta 原则)。⚠ 诚实口径(2026-08-21 评审):db 校验只要求「至少一个出口」,
>   **`yield_gems` 单独仍算合法出口**(机制留在代码里)—— 「零分红」靠出厂 roster 自律,`t_asset` 锁着「出厂 roster 分红为 0」,不是 db 拒绝;
> ③ 收入**不挂绝对分数**(挂通关段数 —— 绕开「赛季挂分改求解器目标函数」的未拍岔);
> ④ **关卡难度设计不带 meta**(08-15 拍板:有道具后简单点正常,但难度不按它标定)。

---

## 0. 核心循环的机制翻译

```
演出收入(按通关段数) ──买──▶ 资产(内容) ──下一局兑现──▶ 想再玩 ──▶ 收入…
```

- **「买了就想玩」= 资产的价值只在下一局里兑现。** 新歌要进到那个场馆才听得到;
  彩带要通关才炸;合约券要开局才领。买完的那一刻只拿到「期待」,兑现必须去玩。
- **「玩了就想买」= 橱窗就是游戏本身。** 免费曲循环第三遍时你知道货架上还有两张唱片;
  结算屏的收入行提醒你钱包在涨。不做任何弹窗/红点 —— 欲望来自内容本身的缺口。

**⚑ 入表判据(db 校验拒纯装饰,这条拒「装饰得不够具体」)**:
**一件新资产必须能回答:「买完后的第一局,玩家在第几拍、什么位置注意到它?」**
答不出来的不上架。现役十一件的答案见 §6 的验收表。

## 1. 现状(2026-08-19 深夜 v2 已实装)

唱片 ×6(场馆歌单加曲;每场馆免费第一首)· **点唱机**(首页奏响免费首曲 + 已购唱片,08-20 落地)· 彩带机(结算彩带 ×2)·
应援团(舞台荧光棒 4→8 + 结算棒海 ×2)· 券合约 ×2(每日加发)。

## 3. 经济设计原则(原则,不是数字 —— 数字归用户手调)

- **第一件 1~2 局够买**(欲望要立刻能兑现一次);**档间距 ≈ ×2~3**(始终有一个
  「跳一跳够得着」的目标);**顶端 = 数十局**(长线钩子)。现表 15→560 符合这条形状。
- **收入侧只有参与**:段数 + 通关。不挂分数(红线③)、不挂日活勾子(签到是另一层的事)。
- **通胀阀**:宝石唯一出口是资产;**回收扩容的唯一手段是上新**。⇒ 表买空 = 收入失去意义,
  这就是 §4 的洞 —— 上新节奏是这个系统的生命线,不是锦上添花。

## 4. 买完之后呢(设计洞,三岔)

| 岔 | 形状 | 判词 |
|---|---|---|
| A. 声望重置 | 清资产换加成/标识再来一轮 | ❌ **违背「拥有物不清零」**(券 vs 角色那条判据:资产是拥有物,到点没收像被抢) |
| **B. 赛季上架窗口** | 赛季限定资产**轮换上架**;买到的**永久保留**,过季只是**下架** | ✅ **推荐,脚手架 08-20 已落地**(`season_now` / `season` / `on_shelf`,出厂无赛季):稀缺性驱动购买,又不没收任何人的东西。⚠ 获取条件挂「赛季内通关次数」(安全),**不挂高分**(红线③) |
| C. 无限阶梯 | 第 11、12…档一直加 | ❌ idle 回本数学回魂 |

B 的最小形状:`assets.json` 加 `season` 键(空 = 常驻),资产页多一条「本季」分组。
上新内容 = 新唱片(音乐管线已通)+ 皮肤(等素材)。

## 6. 验证方案

- **单测**(t_asset 已锁):出口四类 · 阶梯升序 · 唱片指向真实音频 · flair 白名单 ·
  歌单池隔离(俱乐部的唱片漏不进小酒吧)· 探针恒空;
- **拍内注意点验收表**(§0 判据的实测版,试玩逐件打勾):

  | 资产 | 该在哪一拍注意到 |
  |---|---|
  | 唱片 | 进对应场馆的第一拍(音乐起) |
  | 彩带机 | 通关结算瞬间 |
  | 应援团 | 开局第一拍的舞台下沿 |
  | 合约 | 次日第一拍「今日券」飘字 + 托盘 |
  | 点唱机 | 买完回到首页的那一刻(首页从静音变成有歌) |

- **留存**(回传上线后):持有资产数 × 次日回访的分层对比;买入行为要进打点(🟡 岔 #4)。

## 8. META **没盖住**的一块:首页信息栏(2026-08-22 用户问「meta 是否包含了这块」—— 答:没有)

首页 / 四屏顶栏的档案区画了五样:**头像+等级(LV)· 名字 · 称号 · 经验条(XP)· ◆ 金币 · ◈ 宝石**。
本稿 §0–§7 只定义了**宝石 ↔ 资产**,所以只有 ◈ 是真钱包;其余四样在任何系统里都没有定义,
一直是设计稿(`docs/mockups/home.html`)带来的 mock 数(LV.12 / 340/500 / ◆2480)。
**08-22 用户拍板(同日实装)**:「跨局金币可以删 chip,其他按你推荐的来」⇒ 下表「推荐」列就是现行实现:

| 项 | 现在 | 它该是什么系统 | 推荐 |
|---|---|---|---|
| **◆ 跨局金币** | 0 | 不存在。局内金币每局清零是拍板(资产循环「碰不到局内金币」红线) | **删掉这个 chip**,或改成显示「本局起始金币」——后者是真值但没信息量。倾向删 |
| **LV + XP** | 0 / 0/0 | 参与度进度(和宝石收入同源:段数 + 通关)。**不许挂数值加成**(红线:不许永久底倍率) | 做成「演出场次 → 等级」的纯称号进度:XP = 累计通关段数,等级阈值走 `data/assets.json` 一张表;升级只解锁**称号**与头像框,零数值 |
| **称号** | 占位文案 | LV 的产出物 | 随 LV 表给,一档一句 |
| **名字** | 占位文案 | 没有命名系统;单机不需要 | 留占位,或读主角名(选了谁显示谁) |

**实装落点**:等级表 = `data/assets.json profile.levels`(xp 升序 · 首档 0 · 双语称号 · **键白名单只许 xp/cn/name ⇒ 零数值是校验锁的**)·
纯函数 `Asset.level_for(累计通关段数)` → {level, xp, xp_max, title} · `SaveState.profile()` 喂 `stats().sections` · 首页与四屏顶栏共读;
◆ chip 已删(首页与 `Chrome.page_bar`,◈ 单 chip 居中);首页头像 + 名字跟当前主角(`SaveState.hero()`)。阈值 0/4/10/20/35/55/80/110/150/200 是口味值。
成就页同日同口径:`cur` 读终身计数
(`SaveState.stats`:runs / wins / sections,08-22 起 `settle_run_meta` 累加),没有对应计数的四条恒 0 —— 让它们活起来要在
`settle_run_meta` 加对应的事实计数(单拍最高分 / 同花通段 / 四槽同持 / 各主角通关),不是填数。排行页仍是壳(要联网)。
