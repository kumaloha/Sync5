## 0. 一对互逆的关系

**建模服务于一对互逆的关系,别的都不是目的:**

```
                     求解 (forward)
     配置 c  ─────────────────────────▶  表现 P(c)
          ◀─────────────────────────
                     生成 (backward)
```

**上一轮的病根**:这一对关系被**倒过来**用了 —— 不是「先有游戏,再建模去求解它」,
而是「模型能算什么,什么就成了判据;判据不合意时,能动的就只剩内容」。
2026-08-07 改 `lostpage`/`freshsheet` 两个机制不是一时糊涂,是这个结构的**必然产物**:
当时手里只有一把尺子,尺子说这张脸是正分,剩下的选项就只有「改脸」。

**⚑ 所以防止再次倒果为因,靠的不是自律,是结构**:先把**对象**(§2)写死,
再写**谁在玩**(§3)、**测什么**(§4)、**怎么生成**(§5)。
每一层都必须能回答「这是游戏的性质,还是我为了能算而做的近似」(§11)。

## 1. 表现 `P(c)` 是**向量轨迹**,不是标量

### 4.1 为什么

生成的目标是留存(§5)。而留存不是通过率的函数 —— 调研的结论是它由
**近失效应 / 成长感 / 新鲜感**驱动(`docs/design/research_pacing_retention.md`)。
`P` 若只有通过率,生成器就只能对齐一条死亡率曲线,**而那条曲线是拍出来的**。

### 4.2 形式

```
P(c) = ⟨ p(σ), Δ(σ), V(σ), G(σ), N(σ) ⟩ ,  σ 按段(4)或按拍(24)
```

| 分量 | 定义 | 直觉 | 来源 |
|---|---|---|---|
| `p` 通过率 | `Pr[ρ ≥ target]` | 难度 | 求解器 |
| `Δ` 技巧空间 | `E[完美玩家] − E[单拍贪心]` | **会玩和不会玩差多少 = 学会了有回报** | **求解器免费副产品**(λ 开关) |
| `V` 运气占比 | `Var[得分 \| 决策已定] / Var[得分]` | 打完最优之后还有多少在摇 | **求解器免费副产品** |
| `G` 缺口分布 | `(target − ρ)/target` 的分布 | **近失** —— 差一点的密度 | **求解器直接产物** |
| `N` 新鲜感 | 首次出现的脸/卡,带衰减 | 没见过的东西 | **外部编码,求解器天然感受不到** |

⚑ **前四个分量全部是求解器的副产品,只是现在没人去取。**
这是本文成本最低的一条改动:不需要新的求解能力,只需要在现有采样里多记几个量。

⚠ **`N` 是唯一测不出来的** —— 求解器瞬间就懂规则,对「没见过」的反应是零。
由此得到一条可执行的原则:

> **引入新脸/新卡的那一段,通过率应该定得比曲线更松** ——
> 它的**体感**难度比**测出来的**难度高。而「掌握感」正是下一段用同一张脸、
> 通过率回到正常时产生的。

### 4.3 这一层的验证

**主张:这五个分量是独立信息。** 证伪方式:**两两相关系数**。
若 `Δ` 与 `p` 的 `|r| > 0.9`,那多这一维等于零,该合并或说明。**现在就能跑。**

### 1.4 实测:`P` 的分量各带独立信息

单位 = (配置 × 段),K=10 个随机脸排布 × N=30 局 × 2 臂,n=40。

| 分量 | 均值 ± 标准差 |
|---|---|
| `p` 通过率 | 0.206 ± 0.334 |
| `Δ` 技巧空间 | 79.6 ± 103.0 |
| `V` 决策外方差占比 | **0.269 ± 0.032** |
| `G` 近失密度(缺口 ≤30%) | 0.119 ± 0.153 |

两两相关系数**全部 \|r\| < 0.5**,最强的一对是 `p × V` 的 **+0.489**。
**→ 四个分量都带独立信息,「`P` 是向量而不是标量」这条成立。**

⚠ **两条必须一起读的限制**:

1. **`p` 和 `G` 的绝对值不可解读** —— 它们依赖 `section_targets`,而那张表是**占位**(§5.4)。
   相关性仍然有效(同一批配置上算的),**但 20.6% 这个通过率不要拿去做任何设计判断**。
2. **`V` 的跨配置标准差只有 0.032(均值的 12%)** —— 也就是说
   **当前的配置空间(脸的排布)几乎改变不了它**。
   `V` 作为**描述**有效,作为**生成器的优化目标**目前无效:生成器手上没有能拧动它的旋钮。
   要拧动它得换杠杆(手牌大小 / 弃牌规则 / 缓存容量),那属于第 7 类(结构)。
   ⚠ **这正是「有一个量」和「能优化那个量」的区别,不写清楚就会去优化一个拧不动的旋钮。**

⚠ **口径**:`V` 实测的是「牌运方差 ÷ (牌运方差 + 同一手牌下 56 切法之间的方差)」。
它回答的是**「拿到什么牌」相对「怎么切」谁的方差大** —— 27% vs 73%,
**这个游戏是决策主导的,不是发牌主导的**。
⚠ 它**不等于**「最优玩家打完之后还剩多少运气」(那需要另一个分解),`docs/design/gates.md`
写的是后者的口径。两者别混用 —— 待办里留一条:补一个「最优后残余方差」的度量。

## 2. 生成 = 一个优化问题

### 5.1 形式

```
c*  =  argmax_c   U( P(c) )      s.t.  c ∈ 合法配置空间
```

- `c` = 目标分表 · 脸的排布 · 经济 · 货架权重 · 结构参数
- `U` = **留存效用**,目前**未知**

### 5.2 `U` 未知时怎么办 —— 三条纪律

1. **用三因子加权代替**,权重**不拟合**(没有留存数据,拟合出来的权重是假的)。
2. **做敏感性分析**:权重在一大片取值范围里扫,看 top-k 配置变不变。
   不变 → 权重现在不重要,别调它;剧变 → **这个决策依赖一个我们还不知道的数,标「待留存数据」**。
3. **只信同一批配置之间的排序,不信绝对值。** 在真人数据到位之前,
   生成器输出的绝对难度不该被当真(`docs/design/gates.md` 主张 7/8 未校准,乘性误差可达 44%)。

### 5.3 反解目标分仍然是恒等式

给定 `P` 和期望的死亡率 `d`,`target = 第 d 分位数` —— 按定义不可能错。
**所以生成的风险不在这条算术上,而在 `P` 本身**(求解器的覆盖与能力)。
⚠ `death_spec` 现在是 `data/run.json` 的 `[0.10, 0.30, 0.45, 0.60]`,
**是搜索起点不是定论**,且**故意不校验单调性**(「一关比一关难」已从原则降级为假设,
起承転結的「転」本来就不单调)。

### 5.4 ⚠ 两张目标分表的性质

`run.json section_targets` 与 `sim.json bot_targets` 是**占位,不是待修的 bug**
(用户 2026-08-08:「后面要重新设计的,**不是定稿**」)。
它们是本节整套重新设计的**产物**,不是一次可以单独补的算术。

## 3. 层 2:玩家生命周期(只写结构,零数据不填数)

一局之外还有一个决策问题,而**决策者是玩家不是我们**:

```
玩家状态 m = ⟨ 解锁进度, 收藏, 见过的脸/卡集合, 近期战绩, 疲劳, 期望 ⟩
玩家的动作:  再开一局  /  离开
```

- **生成在这一层的作用点** = 「这一局该给什么新东西」(`N` 的来源)。
- `docs/design/levels.md` 的七状态 Director(Establish → Pressure → Introduce → Experiment →
  Mastery → Payoff → Recovery)就活在这一层。
- ⚠ **DDA 被察觉就失效**;L4D 的解法是**改内容不改数值**。
  → **Director 绝对不能调目标分**(玩家看得见),只能调脸的排布和货架。
- ⚠ **`docs/design/ui_meta.md`(meta)整块未做**,而调研判定它是 **D7 的主要风险**。
  在本文的形式里,meta 就是 `m` 的主体 —— **`m` 现在几乎是空的**。

**这一层现在验不了**(零真人数据),所以只写结构与接口。
⚠ **唯一能直接观测这一层的量是「会话边界」**(一次坐下玩几局、隔多久回来),
`docs/design/telemetry.md` 里它被判为「留存指标,不是 G/D 输入」所以没做 —— **目标函数换了之后这个判断过期了**。

## 5. 怎么评估生成出来的关卡

⚠ **模型评估不了「好」** ——「好」最终是留存,而留存零数据。
任何声称能给关卡打分的做法,都是在把一个未知数偷偷写成常数。

但三件事能做,**按硬度排**:

### 5.1 验证生成器**没说谎**(硬判据,能自动跑)

生成器说「这个配置下第 3 段死亡率 45%」→ 拿它自己的输出**真打一遍**,实测是不是 45%。

```
loss = | 预测通过率 − 实测通过率 |
```

这不评估关卡好坏,评估**生成器对不对**。规格见 `19 §4.1`(闭环重放),
现在只对目标分做过,该扩到脸的排布和经济。

⚠ **目标分那一维是恒等式**(查分位数),按定义不会错;**真正会错的是分数分布本身**
——所以闭环重放实际验的是求解器。

### 5.2 测量**形状**(描述,不是评价)

五项难度分解 + 缺口分布按段打出来。它回答「这个关卡是什么样」,不是「好不好」:

- 四级是**同一种难**收了四次费,还是每级换一种?
- 技巧空间大不大(会玩和不会玩差多少分)
- 近失密度(差一点没过的比例)

**判断留给设计者。** 模型的职责是让形状可见,不是替人说好坏。

### 5.3 检测**明显坏**(这条最实用)

**「检测坏」比「评价好」容易得多,而且不需要留存数据。**

| 症状 | 说明什么 |
|---|---|
| 通过率 ≈ 0 或 ≈ 100% | 不可能过 / 白送 |
| **技巧空间 ≈ 0** | 怎么打都一样,玩家学不到东西 |
| 运气占比 ≈ 1 | 全靠运气,决策不重要 |
| 相邻段的难度来源完全相同 | 同一件事收了多次费,阶梯是假的 |
| 缺口分布**双峰** | 要么碾压要么完全过不去,**没有近失** |

这是 `gate.sh` 那套思路的推广:**门不判断好,只拦明显坏。**

### 5.4 能排序,但不能打分

要在一批候选里挑,可以按代理目标排序 —— 但权重未知,所以:
**扫一片权重,看 top-k 稳不稳。**

- 稳 → 这个决策**不依赖**那个未知数,排序可信
- 剧变 → **标注「待留存数据」,别硬选**

（`19 §7.5` 的敏感性分析。它的价值不是给出答案,是**诚实区分「现在能定的」和「必须等数据的」**。）

## 6. 随机搜索的三个陷阱

用户 2026-08-08 定的生成方法:**随机生成大量候选 → 评估 → 选分高的**。可行,但:

### 6.1 ⚠⚠ 搜得越多,选出的越可能是「运气好的」

如果每个候选的评估带蒙特卡洛噪声,「取最高分」会**系统性选中噪声正偏**的那个。
**候选越多,偏差越大** —— 10 万个候选里的第一名,几乎肯定是运气最好的。

两条解法都要用:

- **全部候选共用同一批随机数** —— 噪声成对抵消
- **两阶段**:粗筛 → 对 top-k **用更大样本重新评估**。第一轮的分数只用来筛,不用来排名

⚠ 报**置信区间**,不报点估计。第一名和第十名的差若落在误差里,那是「这十个一样好」。

### 6.2 采样空间要收窄

目标分在 `[0, 100000]` 均匀采样的话,99% 的候选要么不可能过、要么白送。
**用反解给出的 `T` 当中心,在附近扰动** —— 反解是免费的,正好拿来定采样中心。

### 6.3 「分」是多目标合成的,而权重未知

```
第一步  约束筛      通过率∈区间 · 近失∈区间 · 技巧空间>阈值 · 缺口不双峰   ← 不需要权重
第二步  帕累托前沿   给出非支配候选集                                    ← 不需要权重
第三步  加权排序     只在要「给我一个」时做, 并附敏感性分析                ← 需要权重
```

**前两步完全不欠数据。**

⚠ 但**约束的阈值本身也是先验**(技巧空间 > 多少?近失 15-45%?)——它们是调研来的,不是测出来的。
标注成假设,等真人数据校准。**有假设的约束仍然比没有约束好**,因为它把判断显式化了。

## 7. 生成器只有**一个旋钮**

五项难度分解里,`T` 只能拧动第一项:

| 难的来源 | 谁决定 |
|---|---|
| ① 数值压力 | **生成器**(目标分) |
| ② 上界压缩 | **设计者的脸排布** |
| ③ 技巧惩罚 | **设计者的脸排布** |
| ④ 信息惩罚 | **设计者的脸排布** |
| ⑤ 运气暴露 | 实测当前配置空间**拧不动它** |

所以「基于建模生成」**不是**「生成器自动生成关卡」,真实分工是:

> **设计者定脸的排布 → 决定难的「性质」**
> **生成器定目标分 → 决定难的「量」**
> **生成器同时报告 ②③④ 的实测值 → 让设计者看见自己的设计产生了什么形状**

⚑ **第三行才是它对关卡设计最有用的地方。** 举个具体的:排的阶梯如果四级全靠 ① 涨、
②③④ 一条平线,那四级是**同一种难收了四次费**;每级换一种涨才是真阶梯 ——
**而这件事现在一眼就能看出来,不用猜。**

## 8. 需要模型之外的锚才能解的

### III-1 真人是什么样的玩家

`θ = ⟨λ 前瞻, τ 手速, ε 决策质量, d 深度⟩` 对真人的取值。

> **⚑⚑ 2026-08-14 更新:`τ`(手速)这一维不再是零数据了。**
> 写这一节时磁盘上合格局只有 **1** 局;现在是 **12 局 / 168 拍**(2376 个 Tape 文件,
> 其余是探针的不死局,被 `_qualified` 的时长筛挡住)。实测:

| 量 | 真人 | 模型给的 | |
|---|---|---|---|
| 一拍**弃牌**张数 | 均值 1.11(有弃牌的拍 2.30)· **最大 4** | 预算曾是 **2** | 已校准到 4(2026-08-13) |
| 一拍**交换**次数 | 均值 **1.01** · 最大 4 | 预算 5,**有效上限 3**(缓存格数) | 预算不绑定,但**求解器用得满、真人用不满** |
| 一拍**总动作数** | 均值 **2.12** · 最大 6 | 4 + 3 = **7** | **模型的动作空间是真人的 3.3 倍** |
| 动作**时刻**(8s 拍) | 中位 **5.0s** · p90 7.0s · 最晚 7.7s;每拍最后一个动作中位 **5.7s** | 模型无时钟 | — |

> **⚑ 这三行合起来就是本节开头那句「差一次就让全部读数偏三成」的量化版**:
> 求解器不是"比真人聪明一点",它在**动作数量**这一维就有 3.3 倍的空间,
> 而 §7.1 实测交换预算每少一次最优分掉 37.8%。
> ⚠ **注意两个方向相反的偏差**:弃牌那一维模型曾**低估**真人(预算 2 < 真人 4,
> 已修);交换这一维模型**高估**真人(能用 3 次,真人只用 1.01 次)。
> **所以「校准之后目标分偏松还是偏紧」不能从这两个数直接推 —— 要实测。**
> 唯一确定的是:**求解器在两维上都不受真人的手速限制**,所以目标分是完美玩家尺度、
> 对真人偏难 —— 与 CLAUDE.md 那条「就让它偏着」一致。
>
> ⚠ **仍然是零数据的**:`λ`(前瞻)· `ε`(决策质量,只对上了均值,分布形状未验)· `d`(深度)。
> 而 **12 局撑得起拍级统计量**(动作数、触发率),**撑不起局级的**(通关率、构筑成型率)。

已知的量化后果(`solving.md` §7.1,960 拍实测):交换预算从 **2 降到 1**,最优分掉 **37.8%**;
而现值预算下**一个切法都不剪**。**「真人一拍能做几次拖拽」是一个差一次就让全部读数偏三成的开关。**

⚠ 还有一条更弱但同样没锚的:`ε` 现在**只对上了均值**,分布形状(方差、崩盘拍的密度)未验。

### III-2 玩家会学习,模型里不会

`tools/addit.gd` 实测:同一张脸跨段复现,残差只有 **+23.2 ±130** ——
**模型里「第二次」和「第一次」一样疼**,而真人第二次该更容易。

**那个差额就是教学价值**,而起承転結的整条弧建立在它上面。**只能等真人数据。**

### III-3 新鲜感 —— 求解器**结构性地**感受不到

求解器瞬间就懂规则,它对「没见过」的反应是零。**这不是精度问题,是求解器的本性。**
所以新鲜感只能**外部编码**,不能测。

### III-4 好不好玩 / 留存

目标函数是「有一定商业化能力的情况下,留存最大化」。三因子(成长感/赌博感/新鲜感)
写了口径但**权重无数据**,而且**商业化还会再改一次目标函数**。

## 9. ⚠ 不是建模问题 —— 别再当成缺口

> 这一节是本文存在的一半理由。下面每一条我都曾误判过一次。

| 事项 | 它是什么 | 我犯过的错 |
|---|---|---|
| **手写的排布骨架** | **设计意图** | 判成「还没自动化的技术债」,想让生成器去搜它 |
