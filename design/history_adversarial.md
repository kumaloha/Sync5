## 1. 四层架构(2026-08-06 用户拍板重写 —— 旧版把「判别器」和「模拟器」当成一个东西, 是错的)

> 用户原话:「**对抗是数学 G 和数学 D 的对抗, 模拟是模拟**」「**模拟是最后的验证, 前面是不用做的**」。
> 旧版 §1 把 D 定义成 `sim.gd + bot.gd`(真打), 于是「对抗」实际是**数学 vs 模拟**,
> 每转一圈要 4 分钟, 而且把「玩家能力模型」和「验证仪器」两个职责压在了一个东西上。

| 层 | 载体 | 快慢 | 职责 |
|---|---|---|---|
| **数学 G** 生成器 | `tools/model.gd` | 毫秒 | 设计意图(难度谱)→ 关卡配置(targets, 将来扩到脸池/时钟/经济) |
| **数学 D** 能力模型 | 同上(独立模块) | 毫秒 | 关卡配置 + 玩家画像 → 分数分布 → 通过率 |
| **模拟器** 验证仪器 | `tools/sim.gd + bot.gd` | 分钟 | **真打**, 用真规则跑, 验证数学 D 有没有说谎 |
| **真人** 最终真相 | `core/tape.gd` 打点 | 最慢 | 校准「发挥系数」, 最终锚 |

**每层由下一层校准。生成 ↔ 求解的快循环只发生在最上面两层。**

### 1.1 「对抗」= 求解, 不是博弈(措辞纠正)

用户定义:「**对抗说的是生成的关卡, 用数学模拟去解, 最后目标是解出概率控制在一个范围**」
「原始的 GAN 最后识别能力在 50%, 这不是我们要的, 我觉得控制在 **15% 左右的通过率**就好了」。

所以收敛判据是 **|算出的通过率 − 目标| < 容差**, 目标 ≈ 15% —— **求根, 不是极小极大**。
GAN 的 50% 平衡点对应的是「判别器分不出真假」, 我们的 D 不做分辨、只做求解, **类比到此为止**。
⚠ **「对抗」这个词在本文档里保留仅为历史称呼**;真要写循环, 写「生成 ↔ 求解」。
否则后人会照 GAN 字面意思设计出一个空转的循环 —— **两个纯数学模型互为逆运算时, loss 恒等于 0,
转一万圈不产生任何新信息。真正的信息增量只来自「现实(模拟器/真人)与数学不一致」。**

### 1.2 难度 = 1/通过率(用户定义, 全项目通用货币)

三条好性质, 生成器就按它算:
- **可乘**:一局过 4 段, 通关率 = 各段通过率之积 → **总难度 = 各段难度之积**(取 log 即相加,
  与 log 分数空间同坐标系);
- **可读**:1/p = **平均打几局通一次**。15% → 难度 6.7 → 一局 4.9 分钟 → **平均 33 分钟通一次**;
- **打折与千人千面同单位**:容错折扣、按水平托底, 都是在难度上除以一个系数。

现有死亡谱换算(形状是设计意图, 保留;锚点要换, 见 §1.3):

| | S1 | S2 | S3 | S4 | 全局 |
|---|---|---|---|---|---|
| 通过率 | 90% | 70% | 55% | 40% | 13.9% |
| **难度** | 1.11 | 1.43 | 1.82 | **2.5** | **7.2** |

### 1.3 锚在「完美玩家」, 容错靠打折(用户拍板)

用户:「如果是 GAN 的做法, 我认为**只能做最强**, 只不过我们基于最强对抗出来的关卡要
**打点折给人容错**, 还有就是**千人千面的随机策略弱化关卡**。」

- **数学 D 的能力上界 = 完美玩家**(穷举最优), 不是「合理玩家」——上界越干净,
  脏东西越集中在唯一那个折扣系数里, 好查。
- **⚠ 完美玩家必须受真人手速预算限制**(见 §1.4), 否则 ① 决策树无界、数学算不动,
  只能退回蒙特卡洛 = 又变成「用模拟冒充数学」;② 上界落进 §7 警告的幻想区。
- **真人通过率 = 完美玩家通过率 × 发挥系数**。发挥系数是**一个标量**(或每段一个),
  不是复杂模型, **几十局真人数据就能估出来**(Tape 已在记分)。
- 落地分两步:现在按「完美玩家 15%」解一版(**明确偏难, 用途是跑通管线 + 喂一致性测试,
  不是上线值**)→ 拿到真人数据立刻重锚成「真人 15%」。**重解是毫秒级, 贵的只有收数据。**

### 1.4 一致化方案:两边共用同一份计分代码

**计分是确定性的** —— 给定 5 张牌 + 构筑 + 脸, 分数唯一确定(`core/pattern.gd` + `core/settle.gd`)。
所以**数学侧绝不能重新实现一遍计分**(两边分家的头号原因, 且分得隐蔽)。数学侧只做两件
模拟器不做的事:① **枚举**牌面(而非随机抽)② 算**完美决策**(而非照 bot 的规矩打),
然后调**同一份** Pattern + Settle。差异因此被压缩到只剩「枚举 vs 采样」和「完美 vs 实际」,
后者正是要量的发挥系数, 前者必须证明不产生差异 —— 靠下面的测试。

**一致性测试(可进 CI 的断言)**:给模拟器加一个**「完美玩家」队列**, 它不用任何手写规矩,
直接调数学侧的完美决策函数。断言:

```
数学算出的分数分布  ==  模拟器跑完美玩家的实测分布   (采样误差内)
```

不一致 = 当场知道两边分家, 且可按段/按牌型拆开定位。**它把「一致性」从口号变成一条会变红的断言**
—— 规则改了、公式改了、新卡进池了, 它立刻报警。**顺带自动抓 §6 那类「模拟器没跟上规则」的 bug。**

**手速预算 = 数学与模拟共用的同一个常数**(写进 `data/`), 三处共用:
数学 D 的完美决策在预算内求最优 / 模拟器完美队列同预算 / 真人物理上受同样限制。
初值按用户实测:**约 2 次弃牌 + 4-5 次缓存↔手牌交换**(⚠ 鼠标操作口径, 用户注明
「电脑操作手机游戏比较麻烦」, 真机触屏应更快)——**待 Tape 真机数据量化**, 它有毫秒时间戳。

### 1.5 仍然有效的旧纪律

1. **两侧独立、对账在外面做。** 数学 D 与模拟器**不许互相调用对方的策略实现**
   (计分代码共用是对的, 策略共用就没有对账价值了)。
2. **共用货币 = 死亡分布 / 难度**(每段一个数)。设计输入是一条谱, 模拟器输出实测谱, 两谱之差 = 端到端 loss。
   ★ 涉及**人群权重拟合**时换**无条件死亡份额**口径(17 的 (F4))——条件谱对权重非线性。
3. **校准结论随保真度过期**:模拟器的 bot 调得更像人 → 数学 D 重校准 → 全部关卡重生成。
4. ⚠ **验证推到最后的固有风险**:等模拟器说「数学错了」, 前面全建在错假设上。
   **对冲 = 每个数学里程碑跑一次缩水版模拟**(几百局, 十几秒)当冒烟测试, 不当校准。

## 2. G 的内部(v2)

- **原子** = (队列, 窗口) 的单拍分数样本:真实 `Deck/Phrase/Pattern/Settle` 蒙特卡洛,
  带热身拍(20/24 张小丑牌是条件触发, 冷启动会集体哑火)、段位脸池采样(结算影响)、
  bot 同款贪心追牌(`_best_plan`)、弃牌预算 = bot 上限 2/拍。
- **窗口化装配日程**:S1 前半 0 槽 → S1 后半 1(免费 Target)→ S2 前半 2 → 后半 3 →
  S3 起 4 槽拉满;supports 固定为 sim 胜率组合(加法系——**因为要预测的是 bot**,
  bot 就买这些;真人上界是 step 4 的问题)。
- **段分布** = 窗口原子按拍数卷积(重采样), 段间独立假设。
- **反解** = 混合人群(六队列等权)分数分布上取分位:`T_s = quantile(mixture_s, 死亡谱_s)`。

## 5. D 的参数化改造(2026-08-06 用户定调; **公式规格已出 → `design/history_parametric.md`, 待审核**)

> 「bot 我们要设计一个不那么规则的版本, 有参数可以优化的。规则多了, 那就是
> 无法迭代的东西了。」—— 当天的两个实锤:`_best_plan` 缺追四条的计划(每个盲区
> 都要再写一条规则去补);`sim.json` 的信念参数被困在规则骨架里, 只能调力度、
> 改不了没枚举到的行为。

> ⚠⚠ **2026-08-06 架构重写后, 本节的前提变了 —— 先读这段再往下看。**
> 用户拍板「锚在完美玩家 + 打折给容错」之后, **上界不需要「学」, 只需要「解」**:
> 完美玩家 = **在手速预算内穷举最优动作的求解器**, 它调真实的 `Pattern` + `Settle` 评估每个动作,
> 因此 ① 天然免疫「新卡要加新规则」(它不认识卡, 只认识分数)② **不需要任何训练**
> ③ 完全可复现 ④ **按定义就是上界**。
> **于是 `tune.gd` + CEM + `policy.json`(`design/history_parametric.md` 的整个 D-①, 预算 13–40h)在上界这条路上不再必要。**
> 参数化策略 θ 只在要模拟**不完美的人**时才有价值, 而那件事现在由「发挥系数 + 真人 Tape 数据」承担。
> 下面的原文保留为**推导史**(它对「规则化 bot 无法迭代」的诊断仍然成立, 只是解法从「学」换成了「解」)。

**原则:规则只准出现在「动作空间」里, 不准出现在「判断」里。**

- **动作空间(这是游戏机制, 不是策略)**:8 张可见牌取 5 = C(8,5) 共 56 种持法
  (换缓存的全部可达态);持法之下的弃牌子集;商店的 买/刷/换/走。
- **判断 = 一个打分函数** `score = θ · features(action, state)`, 全部行为由 θ 决定。
  现有 bot 的五条手写追牌计划、手调 `_p_chase` 信念**全部退役**(保留为回归基线队列,
  也是 D 的进化史)。

**特征集(~28 维 ★★, 全部从牌面机械推导, 零策略先验;维度清单以 17 §1.1 为准)**:
最大同点数 / 对子数 / 最大同花数 / 最密顺窗与缺口 / 点数和 / 最高点 / 万能数 /
当前成手的 (chips, mult) / **构筑对齐**(持法的型倾向向量 · Target 的 kind-mult 向量,
从 jokers.json 推导不手抄)/ 状态交互(缺口÷剩拍、金币、段序 —— 乘在风险项上;
「缺口大要赌」这类行为**由优化自己学出来, 不写死**)。
追四条不再需要专门规则:「最大同点数」特征在, 优化认为值就会自己去追 —— 这是
参数化强于规则的 litmus test。

**技能旋钮 τ**:动作选择用 softmax(score/τ) 而非 argmax。τ→0 = 最强, τ 大 = 更像
随手玩的真人。**同一套 θ 出一族强度不同的玩家**, 死亡谱按人群混合 → 直接喂回 G 的
mixture(G 的「参照人群」从此有了物理来源)。

**优化器(`tools/tune.gd`, 第三个程序, 与 G/D 并列)**:
- CEM/ES:种群 ~24, 每个 θ 以 ~200 局 sim 评估, 精英重估高斯, ~50 代(小时级, 可后台)。
- fitness 分两阶段:① **能力阶段** = 分数/通关率最大化(D 推向更强的悲观下界;
  ★ 17 定稿为 log 段分 + 不死局评估, 见 (F2));
  ② **拟人阶段** = 真人数据进来后 fitness = −距离(bot 死亡谱, 真人死亡谱),
  D 从「最强玩家」转为「玩家模型」。
- ⚠ 能力阶段的靶盘要**固定一版 targets**(或用 scale-free 的分数):targets 本身会被
  G 重生成, 追着移动靶优化不收敛。
- θ 存 data/ JSON(配置化铁律:优化器写回, bot 只读, 无双写)。

**验收**:优化后 θ 在全部单 target 队列 ≥ 规则 bot;自发学会追四条;
G 的 loss 表在新 D 上重跑, 对抗循环双边转动。

## 7. 教训存档(v1 → v2)

- **拍级模型看不见跨拍增长引擎**(成长牌 forever/经济复利/换旗)——但 G 第一步只需
  预测得准 D, D 的 bot 同样不用这些, 所以 v2 能先转起来;真人上界推迟到 step 4。
- **kit 的选择就是结论**:用加法组合测"上界"测出来的是加法系天花板(mirror 一张
  +1.80 log2 直接翻案)。预测 bot 用 bot 的 kit, 预测真人要搜真人的 kit。
- **无约束弃牌是幻想区间**:d=8 一拍 8◆, 全程收入才 ~45-70◆;真实运营点 d≈1-2。
- 反证探针的价值:「三条买不到」实为策略混淆(triplet 追法下 4.7%→16.4%),
  bot 的 `_best_plan` **没有追四条的计划**(三条只延伸到葫芦)——留给 bot 调优。
