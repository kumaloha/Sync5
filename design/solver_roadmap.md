## 0. 一页纸

**问题**:关卡由一堆数字构成(目标分、Boss 脸、经济、货架)。这些数字定成什么,
才能让通过率落在设计值(≈15%,难度 ≈ 6.7)?而且新卡会持续加入,每次都要重算。

**方案**:两个数学件互相咬合,模拟器和真人在下面兜底。

```
   ┌──────────────────────────────────────────────────┐
   │  G 生成器  ──── 出一版关卡配置 ────►  D 求解器    │   快循环
   │     ▲                                    │        │   毫秒~分钟
   │     └──── 通过率对不上设计值,改 ─────────┘        │
   └──────────────────────────────────────────────────┘
                          │ 定期
                          ▼
                     模拟器(真打)         ← 验证 D 有没有说谎     分钟
                          │ 定期
                          ▼
                     真人(Tape 打点)      ← 量「发挥系数」        看玩的量
```

**四条已拍板的前提**(2026-08-06 用户):
1. 锚在**完美玩家**(最强),关卡按它生成后**打折给人容错**,弱者再走千人千面托底;
2. 难度 = **1/通过率**(可乘、可读 = 平均打几局通一次、与打折同单位);
3. 收敛判据 = **解出的通过率落进目标区间**(≈15%),**不是** GAN 的 50% 平衡点;
4. **要跨拍最优**(用户:「我玩的时候是有在思考的」)。

**这条路线删掉了两块最贵的活**:
- **不训练机器人**(原 `tune.gd` + CEM,13–40 小时,每批新卡重跑)——上界不需要学,只需要解;
- **不回归拟合、不假设分数分布**(连带审查抓出的内生性 / 设计矩阵奇异 / 网格饱和三个坑一起消失)。

## 1. 系统总览:四层,两个循环

| 层 | 载体 | 快慢 | 职责 |
|---|---|---|---|
| **G 生成器** | `tools/model.gd`(改造) | 毫秒 | 设计意图 → 关卡配置 |
| **D 求解器** | 新模块 | 分钟 | 关卡配置 + 玩家画像 → 通过率 |
| **模拟器** | `tools/sim.gd + bot.gd` | 分钟 | 真打,验证 D |
| **真人** | `core/tape.gd` 打点 | 最慢 | 量发挥系数,最终锚 |

**快循环(G↔D)**:出配置 → 解通过率 → 不对就改。一天可以转几百圈。
**慢循环(模拟器/真人)**:验证 D 的近似有没有失真,失真了就回去补 D。

## 2. G · 生成器(完整规格)

### 2.1 生成物:什么才算「一个关卡」

从 `data/*.json` 反推,一局的全部可调数字:

| 维度 | 在哪 | G 生成? | 说明 |
|---|---|---|---|
| **四段目标分** | `run.json section_targets` | ✅ **核心** | D 给曲线,查表即得 |
| **每段 Boss 脸池** | `faces.json pools 0..3` | ✅ | 每张脸有难度价格,排布 = 难度预算分配 |
| **起始金币 / 通关工资** | `economy.json` | ✅ | 影响全局,最贵的一维 |
| **货架稀有度权重** | `economy.json draft_rarity_weights` | ✅ | Target 回池后,它同时决定换旗率 |
| **千人千面偏置 β** | 新增 | ✅ | 按玩家档,只托底不压顶 |
| 单拍时长 8s | `run.json gig_clocks` | ❌ 设计常量 | 节奏已定案 |
| 4 段 × 6 拍 / 每 3 拍商店 | `run.json` | ❌ 设计常量 | 节奏已定案 |
| 卡价档位 / 刷新费 | `economy.json` | ❌ 设计常量 | 手感,不交给搜索 |

⚠ **现状:G 只生成了第一项。** 其余五项是本方案要补的。

### 2.2 输入:设计意图(约束,人定,G 不许改)

```
C1  总难度 = 6.7(通过率 ≈15%)                          ← 用户拍板
C2  难度形状递增 [1.11, 1.43, 1.82, 2.5]                ← 前松后紧, 沿用现有谱
C3  每段脸池 ≥ 2 张                                      ← 否则脸的难度价格不可辨识(见 §4.3)
C4  流派平衡:各 Target 流派通过率极差 < 阈值            ← 不能有流派被判死刑
C5  S1 教学空间:难度 ≤ 上限                             ← 4 段全是墙, 开局就带 Boss 规则
C6  多样性:同一配置下不同 run 不能雷同                  ← 脸随机 + 货架随机
```

**C1/C2 合起来就是「难度谱」**,它是 G 的主输入。现有谱换算:

| | S1 | S2 | S3 | S4 | 全局 |
|---|---|---|---|---|---|
| 通过率 | 90% | 70% | 55% | 40% | 13.9% |
| **难度** | 1.11 | 1.43 | 1.82 | **2.5** | **7.2** |

### 2.3 搜索方法(逐维,从便宜到贵)

**① 目标分 —— 查表,免费。**
「还差多少分」本来就是 D 的状态维度,所以**一次 DP 同时算出所有目标分对应的通过率**,
是一整条曲线。要难度 1.43 就在曲线上找通过率 70% 的那个分数。
**不需要迭代求根**——`design/history_parametric.md` 的 (F13) 牛顿法及其「尾部超调 3 倍」的坑一起作废。

**② 脸的排布 —— 小型组合搜索。**
每张脸把该段难度乘一个系数(难度价格)。排布 = 在难度预算里挑组合,满足 C2 + C3。
⚠ 难度价格**必须由 D 直接算**(把脸的效果喂进 Settle 重解一次),
**不能用回归系数反推** —— 脸的机制本身就在改弃牌和金币(rotation 逼你弃牌、cover 扣币),
回归会把它的效应从中介变量里漏掉,系统性低估难度(审查 H12)。

**③ 经济 —— 粗网格,最贵。**
起始金币/工资影响每一拍的可弃张数,改一个数就要重解整个 DP。
放最后,粗网格(比如工资 2/3/4 三档)搜,不做精细优化。

**④ 货架权重与 β —— 依赖 ②③ 定下来之后。**
Target 回池按**稀有**档 → 一局约 0.5 次换旗机会(旧值一局期望 2.1–2.5 次,用户点名太高)。

**执行顺序**:①(免费)→ ②(便宜)→ ③(贵)→ ④。每层定完往下,不回头精调。

### 2.4 千人千面(已拍板:只托底不压顶)

个性化**只动货架池内权重**,不动任何攻略会写的公共规则(目标分、价格、刷新费)。
- 弱档玩家:货架偏向能救命的牌,等效于给他单独除以一个更大的容错系数;
- 强档玩家:**β = 0,纯天然随机**。难度上限交给固定关卡本身。
- **偏置上限是硬约束**:任意一张牌出现率偏移 ≤2× → 打分权重 β ≤ ln2/2 ≈ 0.35。
  解出来超过上限 = 货架这个杠杆不够用,该换别的(比如多给起始金币),
  **不许把偏置推到穿帮**——个性化一旦被玩家指认,攻略区就会出现「这游戏会读牌」的帖子。

## 3. D · 求解器(完整规格)

### 3.1 为什么必须跨拍

真人一拍里权衡四件事,全是「现在的动作影响以后」:
**钱要留着下拍弃** / **这张 A 留缓存等下拍** / **还差多少分决定要不要赌** / **成长牌要不要喂**。
只算单拍最优会系统性低估上界 → 关卡偏易。

### 3.1b ⚑ 跨拍 DP 已被**平衡贪心**取代(2026-08-06 用户拍板)

> 用户:「我觉得你做不了 DP。**缓存的卡也就 3 张, 未来的小丑牌也没信息。**
> 你只能贪心, 在留下的缓存牌最有可能凑大牌和当前这局手牌就要拿高分之间, 要有个平衡的贪心。」

三条理由都成立, 第三条还是本方案自己的探针量出来的:
1. 跨拍状态本来就小(缓存 3 张);
2. **商店是随机的、未来构筑根本不在状态里** —— DP 假装能算等于自欺;
3. **整个跨拍视野的赌注实测只有 3.8%**(`tools/agree.gd`)。拿 §9 里最大的一块工程
   (也是 §10 标的主要风险)去换 ≤3.8%, 是坏买卖。

**取而代之**(= 原 §10 退路 2 升为主线):

```
value(切法) = 本拍得分 + λ · E[下一拍得分 | 留下的 3 张]
```

- **「缓存潜力」不手写启发式**(同花势/对子势那一套是每张新 Target 都要补规则的老病):
  直接 = `E[下一拍最好能打多少分]`, 用同一套 Solver 采样 —— **自动读 Target(经 Settle)、
  新卡零改代码**,与全局纪律一致。
- **λ 不许拍脑袋**:`tools/lam.gd` 扫出来, 判据是 agree.gd 那条 −3.8% 缺口收窄多少。
- 代价:上界从「理论最优」降级为「**这个策略类里的最优**」。可接受(打折系数本来就吸收它),
  但要**显式声明**;将来可用 2-3 拍的小规模精确 DP 兜一个界。

**✅ 已实测并定案(250 局配对, 空槽)**:

| λ | 均分 | 配对差 | z | |
|---:|---:|---:|---:|---|
| 0.00 | 181.41 | 基准 | | |
| **0.20** | **186.17** | **+4.76 ±1.42** | **+3.36** | ✅ 显著 |
| 0.50 | 185.84 | +4.43 ±1.41 | +3.14 | ✅ 显著 |

**养牌是真的。** λ=0 与天花板(188.6)的缺口是 7.2 分, λ=0.2 追回 **+4.76(约三分之二)**。
**λ 在 0.2–0.5 之间平坦 → 参数不敏感, 不需要精调。** 终值 **λ = 0.2** 存
`data/sim.json solver.lam`(db.gd 校验 lam ≥ 0 且 `lam_samples < 1` 时非零 lam 不许静默失效)。

**闭环验证(agree.gd, 400 局 9600 拍)**——效果精确命中 A/B 指认的那一处:

| | 均值 |
|---|---:|
| 数学侧(缓存全新) | 188.6 |
| λ=0 · 第 2 拍起(缓存=挑剩的) | 181.2 |
| **λ=0.2 · 第 2 拍起** | **186.1** |
| 参照:第 1 拍(缓存本来就全新) | 186.4 |

**第 2 拍起追平了第 1 拍**(186.1 vs 186.4)—— 缓存退化的惩罚基本消除。
整体缺口 **−3.8% → −1.4%**;剩下那点现在的头号嫌疑是**牌堆消耗**(§7 近似 #2)。
⚠ 过程中踩到一个真坑, 记档:**首版给每个切法独立采样未来**, 而 cache_value 量级
与本拍得分相当(≈180), samples=2 时每个切法带 ±70 噪声 → 乘 λ 后灌进比较,
而 56 个切法之间真实差距只有几十分, **贪心退化成随机挑**, 实测 λ 越大分越低
(189.8 → 180.0 → 169.3), 看起来像「想法不成立」, 其实测的是实现噪声。
改**公共随机数**(56 个切法共用同一批补牌, 噪声成对抵消)后 λ=0.8 从 169.3 回到 184.2。
**教训:比较多个候选时, 噪声必须成对抵消, 否则量到的是自己的方差, 会误判掉正确的设计。**

**下一步(未做)**:① 用**配对统计**重算(种子已跨 λ 共用, 配对能把标准误压一个量级);
② `cache_value` 按「留下的 3 张」记忆化(C(52,3)=22100 个键, 命中率高)——
现在每拍 ≈9400 次 Pattern+Settle, 60 局 × 6 档跑 10 分钟没跑完, 是可用性瓶颈。

### 3.2 状态与递推(⚑ 已被 §3.1b 取代, 保留为推导史)

一段 = 6 拍,倒着算,每个局面回答「从这里出发,这段还能过关的概率」。

```
状态  S = (t, c, g, K)
  t = 剩余拍数        0..6
  c = 金币            0..~25
  g = 还差多少分      log 间隔分桶(约 25-30 档), g ≤ 0 = 已过线
  K = 缓存三张的类别  归类后约 50-200 类(见 §7 近似 #3)

终止  V(0, c, g, K) = 1 if g ≤ 0 else 0

递推  V(t, c, g, K) = E     [ max      V(t−1, c−cost(a), g−score(a), K'(a)) ]
                       新手牌H   动作a

通过率 = V(6, 起始金币, 目标分, 起始缓存)
```

### 3.3 一拍之内的动作枚举(全部精髓在这里)

手牌 5 + 缓存 3 = **8 张可见牌**。真实规则:
- 交换免费(拖拽 = 两张对调),**最多 3 次就能把任意「8 选 5」搬进手牌**,
  而手速预算 4-5 次 → **交换预算不构成约束**;
- 弃牌 1 金币/张,可跨手牌与缓存多选,弃完立刻原位补牌;
- 锁定时**只有手牌 5 张计分**,缓存 3 张原样留到下一拍。

于是一拍塌缩成两步:

```
① 选弃牌子集 S ⊆ 8 张可见  (|S| ≤ 弃牌预算 且 ≤ 金币), 花 |S| 金币
   → 弃掉的位置随机补牌 → 仍是 8 张
② 把 8 张切成 (计分的 5 张, 留缓存的 3 张) —— C(8,5) = 56 种切法
```

**② 就是跨拍权衡本身**:同一次切分**同时决定**这拍得分与下拍缓存。
「留一张 A 等下拍」不需要额外建模,它自动出现在 56 种切法的比较里。

计分**调真实的 `Pattern.evaluate_best` + `Settle.run`**(见 §5),绝不重新实现。

### 3.4 整局(四段)

四段的通过率不独立——金币、缓存、构筑跨段带过去。
- **A(准)**:DP 直接铺满 24 拍,段边界做「判生死 + 清分 + 工资 +3◆ + 商店」;
- **B(省)**:逐段 DP,用上一段的出口状态分布做下一段入口。

先做 A(状态量只是 ×4),B 留作降级。
**段间独立假设因此被结构性消灭**(审查 H11 的那条系统性偏差不复存在)。

## 4. 循环与收敛:loss 在哪几层才真有内容

> ⚠ **本节修正一处过度声明。** 我此前说过「两个纯数学模型互为逆运算,loss 恒等于 0,
> 对抗是空的」——**那只对目标分这一维成立**,把 GAN 那层结构砍得太狠了。

### 4.1 四层 loss

| 层 | 比什么 | loss 有内容吗 |
|---|---|---|
| **L1 目标分** | G 查 D 的表 → D 再解一遍 | **恒等于 0**。这一维是纯求根,没有对抗内容 |
| **L2 脸/经济/货架** | G 排出一版 → D 解通过率 vs 设计谱 | **有**。D 的近似(缓存归类/牌堆消耗/成长牌不进状态)在这些维度上会露馅,G 排的组合越极端露得越明显 |
| **L3 模拟器** | D 的预测 vs 真打实测 | **有**。D 全部近似的总账 |
| **L4 真人** | 模拟器 vs 真人 | **有**。发挥系数 + 一切没建模的东西 |

**所以「对抗」是真的,只是不在 L1。** 收敛判据统一为

```
|D 解出的通过率 − 设计值| < 容差          (设计值 ≈15%,即难度 6.7)
```

L1 天然满足;**L2 不满足时改 G 的排布,L3 不满足时回去补 D,L4 不满足时改发挥系数。**

### 4.2 与原始 GAN 的异同(写清楚,免得后人误读)

| | 原始 GAN | 我们 |
|---|---|---|
| D 的任务 | 分辨真假 | **求解通过率** |
| 平衡点 | 判别准确率 50% | **通过率打中 15%** |
| G 的目标 | 骗过 D | **让 D 解出的数落进区间** |
| 信息来源 | D 见过真数据 | **L3/L4 见过真打与真人**;L1/L2 是纯数学 |

**共同的结构**:一个生成、一个评判、互相驱动、迭代到指标落位。这层类比是成立的,
也是本方案的组织方式。**不成立的是「平衡点 = 50%」和「D 靠见真数据学习」**——
我们的 D 是算出来的,它的"真数据"在下面两层。

### 4.3 一条自噬陷阱(必须写进约束)

脸的难度价格靠**同段内不同脸的对比**才辨识得出来。
如果 G 把某段收窄成固定一张脸,该段对比归零 → 下一轮价格算不出来。
**生成器的输出会摧毁自己的输入。** 所以 §2.2 的 C3(每段脸池 ≥ 2 张)是硬约束,不是偏好。

## 5. 一致化:两边共用同一份计分代码

**分家的头号原因是数学侧自己重写一遍计分**,而且分得隐蔽(差 5% 看不出来)。

**纪律**:数学侧只做模拟器不做的两件事——**枚举**牌面(而非随机抽)、**求最优**(而非照规矩打);
计分一律调 `core/pattern.gd` + `core/settle.gd`。差异因此只剩「枚举 vs 采样」「完美 vs 实际」。

### 一致性测试(会变红的断言,进 CI)

给模拟器加一个 **「完美玩家」队列**:不用任何手写规矩,直接调 D 的求解器。断言

```
D 算出的分数分布  ==  模拟器跑完美玩家的实测分布      (采样误差内)
```

不一致 = 当场知道两边分家,可按段/按牌型拆开定位。
**顺带自动抓「模拟器没跟上规则」那类 bug**(比如 §6 的商店数),不必靠人去发现。

### 手速预算 = 三方共用的同一个常数(写进 `data/`)

D 在预算内求最优 / 模拟器完美队列同预算 / 真人物理上受同样限制。
初值按用户实测:**约 2 次弃牌 + 4-5 次缓存↔手牌交换**
(⚠ 鼠标口径,用户注明「电脑操作手机游戏比较麻烦」,真机触屏应更快),**待 Tape 数据量化**。

**这条不只是拟真,它决定数学算不算得动**:预算无界 → 决策树无界 → 只能退回蒙特卡洛

## 10. 风险与退路(诚实版)

**主风险是第 6 步的计算量。** 粗算状态数 ≈ 24 拍 × 20 金币档 × 25 分数档 × 50 缓存类 ≈ 60 万,
每个状态要对新手牌取期望。**关键优化**:一组 (手牌, 缓存) 的 56 种切法的 (得分, 剩余缓存)
**与 DP 状态无关**,只算一次复用到所有状态 —— 昂贵的 Pattern/Settle 调用从「每状态」降到「每样本」。
即便如此,一次完整 DP 预计**分钟级**,不是秒级。

**三级退路**(从轻到重):
1. 粗化分桶(金币/分数/缓存类各降一档);
2. **两层分解**:外层只留 (剩余拍数, 金币, 缺口) 的 DP,缓存**积分掉**;内层单拍精确求解,
   用外层给出的「金币影子价 + 缓存影子价」定权。丢掉的只有**养牌**,其余跨拍权衡都保住;
3. 最差退回**逐拍完美 + 跨拍缺口标记**,上界略偏低 → 关卡偏易(安全向)。

**其他风险**:
- 近似 #2(牌堆消耗)方向未定,是唯一可能把结论推向「偏难」的近似;
- 缓存归类压太狠会让养牌决策失真(退路 2 已是它的极端情形);
- 万能牌让 `Pattern` 的暴力代入涨到 2704 倍/组合,带万能牌的构筑要单独优化;
- **G 的第 8/9 步(脸与经济)是 L2 loss 的所在地**,那里 D 的近似最可能失真,预留返工。
